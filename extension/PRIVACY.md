# SEOSA 가격 기록 확장 — 개인정보 처리

한 줄 요약: **버튼을 누를 때만, 상품 번호와 상품명을, SEOSA 서버 한 곳으로 보냅니다.**
쿠키·계정·방문 기록·다른 탭은 읽지 않고, 확장이 저장하는 것은 버튼을 보일지 여부 하나뿐입니다.

## 언제 보내나요

사용자가 상품 페이지의 **SEOSA 가격 기록 보기** 버튼을 눌렀을 때만 보냅니다.
페이지를 열기만 하거나 스크롤하는 동안에는 아무것도 보내지 않습니다.
같은 상품을 다시 열면 이미 받은 결과를 다시 보여 주고, 다시 보내지 않습니다.

## 무엇을 보내나요

| 페이지 | 보내는 값 |
|---|---|
| 쿠팡 상품 페이지 | 상품 번호(`productId`), 옵션 번호(`vendorItemId`, 주소에 있을 때), 아이템 번호(`itemId`, 주소에 있을 때), 페이지의 상품명 |
| 11번가 · G마켓 상품 페이지 | 페이지의 상품명만 (그 몰의 상품 번호는 보내지 않습니다) |

- 번호는 페이지 **주소**에서, 상품명은 페이지의 `og:title` → 첫 제목(`h1`) → 문서 제목 순으로 읽습니다.
- 확장 내부에서는 콘텐츠 스크립트가 서비스 워커로 사이트 종류(`site`)도 함께 넘기지만,
  서비스 워커는 그것을 검증에만 쓰고 서버로 보내지 않습니다.
- 가격·장바구니·주문·로그인 정보·입력란의 내용은 읽지도 보내지도 않습니다.

## 어디로 보내나요

`https://seosa.ai.kr/api/lookup` 한 곳입니다. 확장의 호스트 권한도 `https://seosa.ai.kr/*` 하나뿐입니다.

- 요청은 확장의 서비스 워커에서 **쿠키 없이**(`credentials: 'omit'`), **리퍼러 없이** 나갑니다.
  그래서 SEOSA 서버는 누가 눌렀는지, 어느 페이지에서 왔는지(주소 전체)를 알 수 없습니다.
- 다른 주소로 넘겨지는 응답(리다이렉트)은 따라가지 않습니다.
- 요청 주소의 쿼리에 상품명이 들어가므로, 일반적인 웹 서버처럼 SEOSA 호스팅(Vercel)의 접속 기록에
  요청 주소와 IP가 남을 수 있습니다. SEOSA 서버는 이 요청으로 데이터베이스에 아무것도 쓰지 않습니다.
- 과도한 호출을 막기 위해 서버가 IP 기준으로 분당 60회까지 받습니다 (메모리 카운터, 저장하지 않음).

## 무엇을 저장하나요

`chrome.storage.local` 에 **`seosaShowButton` (참/거짓) 하나**만 저장합니다 — 상품 페이지에 버튼을 보일지 여부입니다.
이 값은 이 브라우저에만 있고 어디로도 보내지 않습니다. 확장을 제거하면 함께 지워집니다.

## 절대 하지 않는 것

- 쿠키, 로그인·계정 정보, 방문 기록, 북마크, 다른 탭의 주소를 읽지 않습니다 (그런 권한을 요청하지 않았습니다: `cookies` · `history` · `tabs` · `activeTab` · `scripting` · `webRequest` 없음)
- 지원하는 상품 상세 페이지(쿠팡 `/vp/products/…`, 11번가 `/products/…`, G마켓 `/Item?goodscode=…`) 밖에서는 실행되지 않습니다
- 원격 코드를 내려받아 실행하지 않습니다 (모든 코드는 확장 패키지 안에 있습니다)
- 광고·분석 도구를 넣지 않았습니다
- 페이지의 가격이나 결제 흐름을 바꾸지 않습니다. 패널의 판매처 링크는 SEOSA가 이미 쓰는 제휴 링크이며,
  사용자가 직접 눌렀을 때만 새 탭으로 열립니다

## 권한 요약

| 권한 | 이유 |
|---|---|
| `storage` | 버튼 보이기 설정 하나를 이 브라우저에 기억하기 위해 |
| `https://seosa.ai.kr/*` | 가격 기록 API(`/api/lookup`)를 부르기 위해 |
| 콘텐츠 스크립트: 쿠팡·11번가·G마켓 상품 상세 페이지 | 그 페이지에 버튼을 그리고, 누르면 주소·상품명을 읽기 위해 |
