저장소에 보존된 P0 원자료 JSON 9개(before, after~after5, final~final3)를 합산했다. 각 파일은 14턴이며, 총 **126턴**(129턴 주장을 뒷받침하는 추가 3턴 원자료는 저장소에 없음), 검색 도구 호출 102회, GPT 라운드 241회(턴당 1.91), 입력 967,314 토큰(캐시 입력 658,304), 출력 84,008 토큰이다. OpenAI gpt-5.1 단가(입력 $1.25 · 캐시 입력 Preview 실측 129턴, OpenAI gpt-5.1 공개 단가(입력 $1.25 · 캐시 입력 $0.125 · 출력 $10 / 1M) 기준 **약 $2.12(캐시 할인 없는 상한) / 약 $1.36(캐시 반영)**. 검색 도구 107회(쿠팡 호출 또는 캐시). 저장소 단가표에 gpt-5.1 이 없어 `_debug.costUsd` 는 0 — 위 값은 응답 토큰 × 단가다..125 · 출력 $10 / 1M) 기준 **$2.04922(캐시 할인 없는 상한, 반올림 $2.05) / $1.30863(캐시 반영, 반올림 $1.31)** 이다. 저장소 단가표에 gpt-5.1 이 없어 _debug.costUsd 는 0 — 비용은 응답 토큰으로 다시 계산했다.

## 6. 남은 문제와 위험

- **지연 목표 미달**: 검색 턴 ~11.5초. 더 줄이려면 모델(더 빠른 모델·추론 설정) 또는 스트리밍이 필요하다 — 이번 범위에서 바꾸지 않았다.
- **재작성 4~5회/14턴**: 대부분 검증기 오탐(가정·완곡 표현의 새 변형 — "예상하기는 어렵다", "150만 원 근처", "관측 1일, 최저/최고 모두 같은"). 오탐은 오답을 내보내지 않지만 4~7초를 쓴다. 정규식 검증의 한계다.
- **ADPICK 없는 Preview**: Production 은 ADPICK 이 더해지고, v2 는 예산·사양 질문에 검색을 2회 병렬로 한다 → ADPICK 분당 10회/키 한도와 쿠팡 분당 상한을 더 빨리 쓴다(거절되면 그 공급원 결과만 비고 답은 나간다). Production 과 같은 후보 집합으로는 재지 못했다.
- **Production 모델이 다를 수 있다**: Production `OPENAI_MODEL` 은 Sensitive 라 확인하지 못했다(코드 기본값 `gpt-6-luna`). 실측은 gpt-5.1 기준이다.
- **"[RK]" 같은 판매자 표기의 상태 의미는 확인하지 못했다** — 리퍼일 수 있으나 근거가 없어 표시하지 않았다.
- 디버그 레지스트리는 상품명을 70자로 자른다 — 재생 분석 한계(실제 검증은 전체 상품명).
