## 2. 수정한 matcher 규칙 (`api/_offeridentity.js`)

| 규칙 | 내용 |
|---|---|
| 판매처 번호 꼬리 | 7자리 이상 숫자에 붙은 머리 글자 하나는 판매처 번호의 일부로 뗀다 |
| CPU · GPU 부품 | 컴퓨터 판매 글(노트북·데스크탑·조립PC… 또는 CPU+GPU 동시 표기)에서 정규형으로 따로 읽는다. 둘 다 적었고 다르면 `cpu_mismatch`/`gpu_mismatch`, 한쪽만이면 `cpu`/`gpu`(REVIEW), 계열만(«울트라7») vs 정확한 모델이면 `cpu_detail`(REVIEW). 그래픽카드·CPU 단품은 칩이 곧 상품이라 예전대로 모델번호(단 강한 부품번호가 있으면 그쪽이 상품). «코어Ultra5» · «인텔 i7» · «라이젠5» 처럼 머리가 붙은 계열 표기는 그것만으로 컴퓨터의 근거, 맨 «울트라 N» · «i7» 은 다른 근거가 있을 때만 CPU — 휴대폰·워치의 «울트라» 등급을 지우지 않는다(«S25 울트라 5G» · «애플워치 울트라 3») |
| RAM · 저장 | 컴퓨터에서 «32G» → RAM 32GB, «512G» · «1T» → 저장, 용량이 둘이면 작은 쪽(≤64GB)이 RAM. 용량이 셋 이상(선택형)이면 건드리지 않는다 |
| 색 정책 | 모델번호 계열(`code:<모델번호>|본품/부속`)에서 **색을 하나만 적은 본품 판매 글**의 색이 둘 이상 관측되면, 그 모델의 «양쪽 색 미표기» 도 REVIEW. 라일락을 색으로 읽는다 |
| 설명 낱말 | **강한(SKU 수준) 모델번호가 정확히 같고 다른 값이 모두 맞을 때만**, 검토된 26개 광고·기능 문구(`DESCRIPTOR_WORDS`)와 «한쪽에만 붙은 맨 앞 대괄호 꼬리표» 를 무시한다. 양쪽에 서로 다른 꼬리표가 있으면 무시하지 않는다 |
| 브랜드 | `hp`(HP·에이치피·휴렛팩커드) · `asics`(아식스) · 소니코리아=sony. «로지텍G» 의 G 는 하위 상표 |

같이 바꾼 곳: 승격 정책(`_identitypromotion.js`)이 CPU·GPU 충돌/한쪽 사유를 알고, 정규 식별·스냅숏(`snapshotOf`, shadow `identitySnapshot`)에
CPU·GPU 를 **값이 있을 때만** 담는다 — 컴퓨터가 아닌 상품의 스냅숏·키는 예전과 같다. 검수 화면 라벨에 CPU/GPU 사유 추가.

## 8. 배포 주의 — 운영 ACTIVE 그룹 1개는 머지 후 재승격이 필요하다

Phase 5 소비자는 ACTIVE 그룹 구성원의 저장된 식별 스냅숏·canonical 키가 현재 파서 결과와 다르면 그 그룹을 쓰지 않는다(fail-closed).

그래서 **머지·배포하면 이 그룹은 새 matcher 로 다시 승격하기 전까지 소비 화면에서 빠진다**(잘못된 가격 비교를 보여 주지는 않는다).
`test-canonical-consumer.js` 가 이 사실(옛 키 비재현 + stale 그룹 fail-closed)을 단언으로 고정한다. 재승격은 운영 DB 쓰기라 이 PR 에서 하지 않았다.
