# Independent synthetic development evaluation — audit notes

Registration: `preregistration.json` (320 synthetic questions; development 200, holdout 120). This document covers only the development split. No holdout data was opened during development.

Run `node scripts/search-eval/run-codex-independent-dev.cjs reports/codex-independent-20261116/<new-unique-name>.json`. The evaluator refuses to overwrite existing output or run if development inputs do not match preregistered SHA-256 values. The provider stub supplies each question's five synthetic candidates, then the real `relevantItems` filter, search API handler, relevance ranking, product gate, and `saveProducts` run; external fetch, rate limiter, trust and facets are mocked, as is the database. Each shown/saved candidate is matched by its unique fixture ID to the preregistered answer. Unknown evidence is not counted as correct. The evaluator records loss stages, with results bounded by the mocked provider pool.

Baseline `development-run-20261116.json` was created at 2026-11-16T04:04:04.786Z. Its four search component file hashes equal the corresponding files at merge commit `1b7c80fda90875e89c2c2e1ea6e672a06ed3f32b`, after applying the Windows CRLF checkout transformation. Other dependencies were not fingerprinted in that baseline, so a fully clean entire-tree state cannot be proven. The evaluator was subsequently extended to fingerprint all top-level `api/*.js` files and detect changes during later runs; this extension does not alter judgments or the preserved baseline result.

Baseline: question PASS 25, FAIL 143, UNVERIFIED 32; displayed top-five slots 256, of which 147 verified correct, 48 known wrong, 61 unverified; lower-bound precision 57.42%; 49% synthetic pool target recall at 10; 95 zero-result questions. These numbers are not population estimates, real-catalog recall, or real provider latency. Each synthetic question uses one of eight repeated templates across 25 development categories, and artificial low prices can affect price guards. No claims are made about 95% service accuracy or production readiness.

Mocked product upserts: 210 rows, including 36 conflicts against a stated requirement and 29 with missing evidence. The latter break down as unknown condition 24, missing requested attribute 4, and absent brand 1. A stored row is a recorded mock upsert, not proof of a production DB write or a distinct real product. Example of an attribute conflict: a 300ml water-tank request displayed and mock-stored a 200ml item. Example of unverified evidence: a `신품만` request mock-stored a listing with no stated condition. Sample excluded brands and accessory-only listings were also verified against their synthetic titles. This was a sample check, not human validation of all 200 answer records.

The benchmark is based on a provider returning the preselected pool, not on live provider search. Evidence is insufficient to distinguish real-world inventory absence from real provider retrieval omission. The loss-stage counts explain this synthetic run only. No additional score was substituted for the baseline, and no holdout answer or rubric file was opened.
