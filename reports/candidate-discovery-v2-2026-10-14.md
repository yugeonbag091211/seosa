# Product Identity — Candidate Discovery v2 (2026-10-14)

> **한 줄 요약** — 판매처 교차 동일상품 그룹 **300 → 304** (알려진 판매처 기준 **136 → 137**),
> 묶인 상품 행 **870 → 877**, 후보 쌍 **82,827 → 97,136**, 새 MATCH 5쌍 수동 감사 오병합 0 ·
> 최종 판매처 교차 MATCH 층화 표본 162쌍 오병합 0, 기존 hard-negative·회귀 0.
> **후보 탐색은 병목이 아니었다.** MATCH 될 수 있는 쌍을 기존 blocking 이 놓친 비율은 1% 미만이고,
> 놓친 동일상품의 대부분은 matcher 의 증거 규칙(REVIEW/NO_MATCH)에서 멈춘다.

원칙은 그대로다: **false merge ≫ missed merge.** `parseOffer` · `matchOffers` 는 한 글자도 바꾸지 않았다
(`_offeridentity.js` 의 변경은 `_internal` export 한 줄). 운영 DB 에 쓰지 않았고, canonical promotion 도 하지 않았다.

3. 쿠팡: 23,642행의 **68%** 가 모델번호도 모델 번호(앵커)도 없다 → 현재 증거 위계로는 MATCH 불가. 교차 그룹 포함률 0.10%.

### 사례 — HyperX 오멘 MAX 16-AH1075TX

롯데홈쇼핑·Hmall 쌍은 ACTIVE canonical 그룹이다. SSG·오늘의집 판매 글은 **이미 후보였다**(`c:16ah1075` 키 공유).

후보 탐색으로는 이 사례를 풀 수 없고, 풀어서도 안 된다(matcher 정책 변경 = 별도 PR + 감사).

## 2. 변경점 — `api/_offerdiscovery.js` (오프라인 전용)

Phase 1 키를 그대로 두고 **덧붙이는** 후보 키만 만든다. 판정은 같은 `matchOffers` + 같은 `contextFactory`.

| 출처 | 내용 | 새 후보 쌍 | 새 MATCH |
|---|---|---|---|
| `mpn` | 원문 영숫자 조각을 이어 붙인 모델번호 — `16-AH1075TX = 16AH1075TX = 16 AH1075TX = 16 AH 1075 TX`, 꼬리 영문 뗀 줄기, 숫자만 있는 스타일 코드(`880840-603`) | 3,343 | 0 |
| `short_code` | 숫자가 적어 parseOffer 가 모델번호로 안 읽는 하이픈 코드 (`BZ-AX1` · `LZHD-H05`) | 1,531 | 1 |
| `family` | 브랜드(없으면 제목 앞 두 낱말) + 첫 앵커 + 등급, 낱말 Jaccard ≥ 0.2 | 7,165 | 5 |
| `words` | 앵커·모델번호 없는 상품의 계열 낱말 서명 (REVIEW 로만 이어진다) | 3,244 | 0 |

(출처가 겹치는 쌍이 있어 합은 14,309 보다 크다.)

- **한/영 표기**: `KEY_ALIASES`(오멘↔omen 등 32개)는 키에만 쓴다. matcher 의 낱말은 그대로다.
- **잡음 거르기** (운영 스냅숏에서 관측): `USB 3.0` · `Wi-Fi 6` · `Win11 Home` · `M.2 NVMe` 같은 규격 이음, `26년` · `1등급` · `2채널` ·
  `100%` 의 숫자 앵커, `[룽스_6820]` · `[예스24배송]` 같은 판매자 꼬리표 숫자는 키로 쓰지 않는다.
- **판매처**: 표시 판매처가 다르면 교차(`ADPICK/SSG` ≠ `ADPICK/롯데홈쇼핑`). 라벨 없는 `ADPICK` 은 «모름» — 같은 판매처라고 단정하지 않는다.
  알려진 같은 판매처 쌍은 v2 후보로 만들지 않는다(같은 몰 중복 찾기가 목적이 아니다). 합치기는 교차 쌍부터.
- **재탐색(`rediscover`)**: baseline 군집에서 구성원을 빼지 않는다. 붙이거나 합칠 때 두 군집의 **모든** 교차 쌍이 MATCH 여야 한다.
  Phase 1 블록 안에서 MATCH 인데 greedy 순서 탓에 갈라진 쌍도 다시 본다(이번 데이터 1쌍 — 제3 구성원과 REVIEW 라 합치지 못함).

## 3. 정확도 보호장치

- matcher 무변경 — 같은 스냅숏에서 `npm run eval:offer-identity-real` 출력이 baseline 과 **완전히 같다**(타이밍 제외).
- all-pairs 관문 · 모르는 값은 와일드카드가 아님 — REVIEW 쌍은 합치지 않는다.
- 옵션 서명(용량·메모리·색·규격·수량, `1개` = 표기 없음)으로 큰 버킷을 나눈다. MATCH 가 나려면 이 값들이 같아야 하므로
  나눠도 MATCH 를 잃지 않는다 — 픽스처 전수 MATCH 쌍으로 검증. `∅` 는 자기 칸이다.
- 버킷 상한 200 · 군집 상한 50. 상한을 넘는 버킷은 건너뛰고 센다(이번 운영 데이터 0).
- 운영 경로 소비자 0 — 검색·AI·상세·shadow 워커·workflow 어디서도 이 모듈을 부르지 않는다(테스트로 고정). 기능 플래그도 없다.

## 5. 수동 감사

- **새 MATCH 5쌍 전수** — 키친에이드 7컵 푸드프로세서 화이트(오늘의집↔롯데홈쇼핑, 5KFP0719 WH) · 미쟝센 파워스윙 매트왁스9 80g ×2쌍 ·
  르젠 퓨어미스트 가습기 LZHD-H05 · 브라이트스타트 기글 사파리 바운서2(쿠팡↔ADPICK). **5/5 같은 상품**(모델·용량·색·수량·신품·본품·구매 일치).
  새 MATCH 가 5쌍뿐이라 «새 MATCH 100건» 표본은 만들 수 없었다.
- **최종 판매처 교차 MATCH 층화 표본 162쌍** (기타 25 · 패션 25 · 화장품 25 · 가전 25 · PC 주변기기 23 · 음향 21 · 생활 9 · 식품 5 ·
  노트북 2 · 저장장치 2 — 운영 군집에 스마트폰 교차 그룹이 없어 0) — **오병합 0**.
  - 단, 색 옵션이 있는 모델인데 **양쪽 다 색을 안 적은** 쌍이 약 21쌍(13%) 있다 (G304 LIGHTSPEED · 소니 WH/WF-1000XM6 · 로보락 S8 Pro(+) 등).
    모델·상품 페이지 단위로는 같지만 색 SKU 는 제목만으로 확인할 수 없다 — Phase 1 의 알려진 한계이며 이번 변경과 무관하다.
    원인: `lineDimensionsOf` 의 계열 키가 첫 앵커를 요구해, 모델번호로만 식별되는 상품(G304)은 «계열에 색이 여럿» 을 보지 못한다.
  - Tier B 앵커가 가짜인 MATCH 가 있다(`1인용` 의 1, 판매자 꼬리표의 6820). 제목 낱말이 전부 같아야 해서 실제 오병합은 없었다.
- **v2 가 새로 올린 REVIEW 표본 120쌍** — 같은 상품으로 보이는 쌍 약 30%, 불명확 약 7%, 다른 상품 약 63%.
  `words` 출처(모델번호 없는 동일 제목)는 대부분 같은 상품이고, `family` 출처는 같은 계열의 다른 변형(색·코드·용량)이 대부분이다.

## 6. 회귀

CI 와 같은 LF 체크아웃 두 벌(HEAD · HEAD+변경)에서 실제 npm script 를 돌렸다 — `npm test` · `test:regression` · `test:release` ·
`test:search`(adversarial 포함) · `test:offer-identity` · `test:identity-shadow` · `test:identity-promotion` · `test:identity-review` ·
`test:canonical-consumer` · `test:live-redteam-regressions` · `test:ai-security-fuzz`: **모두 통과, 요약 줄이 baseline 과 같다**
(차이는 새 테스트 2줄 · 타이밍 · 무작위 주문번호뿐). 새 테스트: `test-offer-discovery.js` 93/93, 뮤테이션 7/7 killed.

중간에 Phase 3 가드(«canonical 표 이름은 승인된 파일에서만»)가 평가기 주석의 표 이름을 잡았다 — 주석을 고쳤다(평가기는 canonical 표를 읽지 않는다).

참고: Windows 의 `core.autocrlf=true` 체크아웃에서는 `test-identity-review-mutations.js` 의 `hard-conflict server gate` 와
`test-identity-promotion-mutations.js` 의 `missing model number blocker` 가 이번 변경 전부터 실패한다(변형 대상이 `\n` 줄바꿈을 기대).
둘 다 이 브랜치가 건드리지 않은 파일이고, LF 체크아웃·CI 에서는 6/6 · 5/5 통과한다. 새 뮤테이션 스크립트는 원본을 LF 로 읽어 이 문제를 피한다.
