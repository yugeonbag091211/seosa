## FIX-02 — 검색어 토큰이 하나도 안 걸린 상품을 결과에서 뺀다

### 증상 (운영 실측, 2026-11-23 23:0x KST)

`/?q=LG 그램 16` 을 **최저가순**(이 서비스의 핵심 약속)으로 본 결과:

```
 1위     699원  올가드 보습 스파 핸드 마스크 16g            ← 핸드팩
 2위   7,920원  LG 그램16 16Z90TL 키스킨
 3위   8,480원  액티비아 컵 딸기 16입 (80gx16개)            ← 요거트
 4위   8,600원  … 5G 무제한 데이터 SIM 카드 (LG U+)         ← 유심
```

1위 상품의 `scoreTitle` 은 `score 0 · hits []` — 검색어의 어느 토큰도 정확히도,
부분문자열로도, 어간으로도, 합성어 조각으로도, 동의어로도 제목에 없다.

### 원인

`api/_search.js` `rankItems()` 의 통과 조건이 `s.r.score >= minScore` 이고
`api/search.js` 는 `minScore: 0` 을 넘긴다. `0 >= 0` 이라 그대로 통과했다.

`minScore: 0` 은 의도된 값이다(«지금까지 보이던 상품이 갑자기 사라지는 쪽이
섞여 보이는 쪽보다 나쁘다»). 그 결정은 뒤집지 않았다. **0 은 «관련도가 낮다» 가
아니라 «관련이 하나도 확인되지 않았다»** 라서 다르게 다룬다.

곱해지는 관계 계수(`titleRelation` · `variantRelation` · `conditionRelation` ·
`substituteRelation` · `productFocus`) 중 0 을 돌려주는 것은 **하나도 없다**
(가장 낮은 값이 0.25, `ACCESSORY_TIER`·`COMPONENT_TIER` 최소 0.45).
그래서 `relevance === 0` 이 되는 길은 «토큰 0개 일치» 하나뿐이다.

### 바꾼 파일

| 파일 | 내용 |
|---|---|
| `api/_search.js` | `rankItems()` 통과 조건을 `score > 0 && score >= minScore` 로 |
| `scripts/test-search-zero-coverage.js` | 신규 회귀 테스트 (13검사, 외부 호출 0 · DB 0) |
| `scripts/test-search-ranking-intent.js` | `notAbove()` 헬퍼 추가 — 아래 설명 |
| `package.json` | `test` · `test:search` 체인에 추가 |

신규 테스트: 수정 전 **10/13 PASS (3 FAIL)** → 수정 후 **13/13 PASS**.

### 기존 테스트를 고친 부분 — 반드시 보고 넘어갈 것

`test-search-ranking-intent.js` 가 20검사 실패했다. 원인은 회귀가 아니라
**픽스처의 «무관 상품»(라벨 D)이 목록에서 사라졌기 때문**이다. 기존 헬퍼

```js
function above(ranked, better, worse) {   // worse 가 «남아 있을 것» 까지 요구한다
  const a = positions(ranked, better), b = positions(ranked, worse);
  return a.length > 0 && b.length > 0 && Math.max(...a) < Math.min(...b);
}
```

사라진 항목은 `positions(...)` 가 빈 배열이라 `b.length > 0` 에서 실패한다.

사라진 것이 무엇인지 전수로 확인했다 — 수정 전/후 모듈로 픽스처 전부를 돌려
사라진 항목을 라벨별로 세었다.

| 라벨 | 사라진 수 | 수정 전 relevance | 예시 |
|---|---|---|---|
| D (의도적 무관) | 21 | **전부 0** | `삼성`→`대나무 주방 도마`, `애플`→`나무 식탁`, `LG`→`우드 수저통` |
| B (같은 브랜드 다른 제품군 / 이웃 모델) | 6 | **전부 0** | `아이폰`→`애플 아이패드 태블릿`, `에어팟`→`애플 아이폰17 스마트폰`, `14ZD95U`→`16Z95U` |
| A (본품) | **0** | — | — |
| C (호환 부속) | **0** | — | — |

본품과 부속은 한 건도 사라지지 않았다. 사라진 27건은 **전부 수정 전에도
relevance 0** — 엔진이 이미 «관련 없음» 이라고 말하던 것들이다.

그래서 체크가 지키려는 명제(«무관한 것이 관련 있는 것보다 위에 오지 않는다»)를
그대로 둔 채 «아예 빠졌다» 도 통과로 보는 헬퍼를 추가했다.

```js
function notAbove(ranked, worse, better) {
  const a = positions(ranked, better), b = positions(ranked, worse);
  if (!a.length) return false;              // better 가 사라지면 그건 진짜 회귀다
  return b.length === 0 || Math.max(...a) < Math.min(...b);
}
```

`better` 쪽이 사라지면 여전히 실패한다 — 테스트를 약하게 만들지 않았다.
바꾼 체크는 6곳(D 비교 4곳, 모델 이웃 비교 2곳)이고 나머지 체크는 그대로다.

적용 후 `test-search-ranking-intent.js` **151/151 PASS**.

  부속이 본품보다 싸서 그렇고, 그건 F-05(판매 대상 판정)의 몫이다. 거짓말이
  하나 줄었을 뿐 «최저가 1위가 노트북» 이 된 것은 아니다.

  수정 전에도 relevance 0 으로 맨 아래였으니 노출 가치는 사실상 없었지만,
  «비슷한 모델도 보여 달라» 가 제품 요구라면 그건 대체 추천(`/api/alternatives`)이
  맡아야지 토큰 0개 일치로 끼워 넣을 일이 아니다.

## FIX-03 — «매일 기록한다» 는 보장되지 않는 주기 주장을 없앤다

### 증상

상품 페이지의 meta description(= 검색 스니펫)이 이렇게 나갔다.

> … 현재 쿠팡 18,920원(11/23 기준). SEOSA가 **매일 기록한** 가격 추이와 구매 시점 판정을 확인하세요.

같은 페이지의 본문은 이렇게 적는다 — 그리고 이쪽이 사실이다.

> 가격 기록이 최대 **77일** 끊긴 구간이 있어 그 사이 움직임은 알 수 없다
> SEOSA가 관측한 **11번**의 가격 중 …

### 측정 — 사이트맵에서 뽑은 상품 12개의 실제 기록

`/api/history?__route=product&pid=…` 의 `points` 를 그대로 셌다.

| 관측 수 / 기록 구간 | 12개 분포 |
|---|---|
| 95.5% · 9.2% · 7.5% · 86.8% · 8.1% · 11.9% · 13.4% · 16.4% · 42.9% · 40.0% · 96.2% · 100% | |
| 구간의 모든 날에 관측이 있는 상품 | **1 / 12** |
| 최대 공백의 중앙값 | **15일** |

12개 중 11개는 «매일» 이 아니다. 이 문구는 사이트맵이 광고하는 상품 페이지
**21,980개**의 검색 스니펫에 실린다.

### 바꾼 파일 (전부 사용자에게 보이는 문구, 로직 변경 없음)

| 파일 | 자리 | 전 → 후 |
|---|---|---|

| `api/_seo-pages.js` | 카테고리·브랜드 description (2곳) | `SEOSA가 매일 기록해 비교합니다` → `SEOSA가 기록해 비교합니다` |
| `api/_seo-pages.js` | 카테고리 허브 본문 | `SEOSA 가 매일 가격을 기록하는 상품을` → `SEOSA 가 가격을 기록하는 상품을` |

코드 주석은 그대로 두었다 — 사람에게 보이는 문구가 아니고, 그 자리에서 왜
그렇게 했는지를 적는 기록이라 지울 이유가 없다.

### 회귀

`매일 …(기록|수집|갱신|업데이트|확인)` 문구가 남아 있으면 실패한다.
meta description 이 현재가·160자 상한·«가격 추이» 안내를 그대로 유지하는지도
함께 본다. `package.json` 의 `test` 체인에 `test-seo.js` 바로 뒤로 넣었다.

이 테스트는 처음 돌렸을 때 내가 놓친 **5곳**을 더 찾아냈다(홈 meta description,
