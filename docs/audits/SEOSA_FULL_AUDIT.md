## F-01 (P1) 상품명 한 건이 범주어 검색을 브랜드 검색으로 뒤집는다 — **수정함**

### 원인

`api/_search.js` `analyzeQuery()` 의 `primaryHead` 가
«머리 토큰으로 시작하는 상품명이 **하나라도** 있으면» 그 검색어를 대표 머리
질의로 본다. 토큰이 하나뿐이면 `intent = 'BRAND_ONLY'` 가 되고,
`titleRelation()` 의 `late-head` 규칙이 «머리 토큰이 3번째 이후에 나오는» 제목에
`×0.65` 를 먹인다.

한국어 상품명은 범주어가 맨 뒤에 온다(«… 가벼운 운동화», «네스프레소 … 커피머신»).
그래서 **진짜 상품만 전부 감점**되고, 범주어로 시작한 엉뚱한 항목(책 등)만 1.00 으로 남는다.

### 운영 실측 ①  `커피머신` (2026-11-23 22:4x KST, `X-Seosa-Source: stale-cache`)

```
 1.  15,300원 rel=1.00  [국내도서] 커피머신 첫걸음              ← 책
 2.  17,100원 rel=0.90  [해외] 데롱기 … 물탱크 덮개 액세서리
 3. 668,600원 rel=0.90  필립스 라떼 클래식 1200 전자동 커피 머신
 4.  64,000원 rel=0.65  카누 바리스타 페블 커피머신            ← late-head
 5.  68,800원 rel=0.65  돌체구스토 지니오S 베이직 캡슐 커피머신   ← late-head
 …   실제 커피머신 8건이 전부 0.65
```

### 운영 실측 ②  `운동화` (2026-11-23 22:05 KST, `X-Seosa-Source: stale-cache`)

1위가 `[국내도서] 운동화 신은 뇌` (1.00), 실제 운동화 19건이 전부 0.65.

★ 정확히 적는다: 같은 검색어를 22:5x KST 에 다시 부르니 `src=api` 로 11건이
왔고 그 후보 집합에는 저 책이 없어서 결함이 **나타나지 않았다**. 즉 이 결함은
«항상» 이 아니라 **후보 집합에 머리로 시작하는 엉뚱한 상품명이 섞이면** 나온다.
그때 멀쩡한 상품이 전부 35% 깎인다.

### 수정

`primaryHead` 성립에 머리로 시작하는 상품명이 **둘 이상** 필요하게 했다
(`PRIMARY_HEAD_MIN_TITLES = 2`). 브랜드는 여러 상품명의 맨 앞에 온다 —
`detectBrandHead` 주석이 이미 그렇게 적고 있고, 운영 실측도 그렇다
(«삼성 갤럭시» 6/6, «운동화» 1/20, «커피머신» 1/17).

### 효과 측정 — 운영 후보 집합 21벌 재생 (외부 호출 0)

2026-11-23 에 `/api/search` 가 실제로 돌려준 상품 목록 21벌을 수정 전/후 모듈에
그대로 통과시켰다.

| 지표 | 값 |
|---|---|
| 영향받은 검색어 | **3 / 21** (운동화 · 커피머신 · 게이밍 노트북) |
| relevance 가 오른 상품 | **33건** (전부 감점당하던 진짜 상품) |
| 1위가 바뀐 검색어 | 1건 — 운동화: «[국내도서] 운동화 신은 뇌» → «이더커머스 남성 발편한 가벼운 운동화» |
| 순서가 전혀 바뀌지 않은 검색어 | 18 / 21 |

커피머신은 1위가 그대로 책이다 — 동점(1.00) 상태에서 가격순 타이브레이크가
결정하기 때문이다. 그건 F-05 의 몫이고 이 수정의 범위가 아니다. 다만 실제
커피머신 8건이 0.65 → 1.00 으로 올라 4~8위에서 2~8위로 이동했다.

회귀 결과는 `SEOSA_FIX_LOG.md` 참고 (전 스위트 175단계 전부 수정 전과 동일하게 PASS).

## F-03 (P2) 검색 응답과 상품 페이지가 CDN 캐시를 전혀 쓰지 않는다 — 미수정

| 주소 | Cache-Control | Vercel 캐시 |
|---|---|---|
| `/api/search?keyword=…` (22개 전부) | `no-store, max-age=0` | — |
| `/p/:pid` | `no-store, max-age=0` | MISS |
| `/api/hotdeals?view=today-drop` | `no-store, max-age=0` | MISS |
| `/category/:slug`, `/brand/:slug` | `public, max-age=0` | MISS/HIT |
| `/api/init` | `public, max-age=0` | STALE(=캐시 사용) |
| `/` | `public, max-age=0` | HIT |

원인: `api/search.js` 와 `api/_product-page.js` 가
`Canonical.config().enabled && percent > 0` 이면 무조건 `noStore(res)` 한다.
운영에 `IDENTITY_CANONICAL_CONSUMER_ROLLOUT_PERCENT > 0` 이 켜져 있어
«롤아웃 중» 분기가 상시로 걸린다.

규모: 사이트맵이 광고하는 상품 URL 이 **21,980개**(`/sitemaps/products-1..15.xml`
합계, 중복 0). 그 전부가 크롤될 때마다 함수 + DB 를 친다.

같은 검색어를 6번 연속 부른 실측(전부 `X-Seosa-Source: cache` — 공급자 호출 없음):

```
7.72s · 1.80s · 3.65s · 0.88s · 1.25s · 1.39s      (total)
```

즉 공급자를 한 번도 부르지 않는 «완전히 같은 응답» 조차 매번 0.9~7.7초의
함수+DB 작업을 다시 한다. 그 위에 `_canonicalconsumer.resolveGroups` 가
검색 한 번마다 DB 질의 4회 + `attachTrust` 를 더한다.

바꾸지 않은 이유와 필요한 결정은 R-02.

`GET /api/hotdeals?view=today-drop&limit=60` 의 사진 주소 60개를 전부 받아 봤다.

| 호스트 | 결과 |
|---|---|
| ads-partners.coupang.com | 40 OK |
| shop2.daumcdn.net | 7 OK |
| eyoumall.godohosting.com / res.klook.com | 2 OK |
| **d2iaagr1j041pi.cloudfront.net** (ADPICK `search_img.php`) | **10 × 404** |

= **10 / 60 (16.7%)** 이 죽은 주소다. ADPICK `search_img.php?code=` 는 발급 직후에만
열리는 임시 토큰이고, 이 사실은 코드 주석에 이미 실측으로 적혀 있다.

화면은 깨지지 않는다 — 웹은 `document` 캡처링 `error` 리스너가 사진을 숨기고
글리프(✦)를 넣고(실측 확인: 카드 5장 중 1장이 그 상태, 썸네일 높이 56px 유지),
모바일 앱도 `components/Thumb.tsx` 의 `onError` 로 같은 처리를 한다.
그래서 «깨진 이미지» 가 아니라 «사진 없는 카드 + 낭비된 요청» 이다.

`api/_seo.isDurableImage()` 가 바로 이 주소를 걸러내는 규칙을 이미 갖고 있지만
og:image·JSON-LD 에만 쓰인다. 핫딜 카드(`api/hotdeals.imageFor`)는 통과시킨다.
고치려면 «사진 없는 카드로 내보낸다» 와 «그대로 두고 클라이언트 폴백에 맡긴다»
중 하나를 골라야 하고, 사진이 아직 살아 있는 카드까지 잃는 쪽이라 제품 판단이 필요하다.
덧붙여, 죽은 사진을 다시 채우는 백필은 F-02 로 멈춰 있는 `SEOSA HOT` 안에 있다.

```
 3위   8,480원  액티비아 컵 딸기 16입 (80gx16개)            ← 요거트
 4위   8,600원  … 5G 무제한 데이터 SIM 카드 (LG U+)         ← 유심
```

최저가 비교 서비스에서 «가장 싼 것» 자리에 699원 핸드팩이 선다.

### 원인

1위의 `scoreTitle` 은 `score 0 · hits []` — 검색어 세 토큰(`lg` · `그램` · `16`)이
정확히도, 부분문자열로도, 어간으로도, 합성어 조각으로도, 동의어로도 제목에 없다.

그런데 `api/_search.js rankItems()` 의 통과 조건이 `score >= minScore` 이고
`api/search.js` 가 `minScore: 0` 을 넘기므로 `0 >= 0` 으로 통과했다.

### 범위 (실측)

운영 검색어 33개 · 상품 506건 중 `relevance === 0` 은 **2건(0.4%)**.

```
  LG 그램 16          : 올가드 보습 스파 핸드 마스크 16g
  아이폰17 프로맥스 256 : 8H 방탄필름 액정보호 2매 갤럭시A25 5G A256
```

둘 다 명백한 무관 상품이고, 진짜 상품이 0 을 받은 사례는 없었다.
0 보다 큰 낮은 점수(0.125 등)에는 진짜 상품이 섞여 있으므로
(`[자급제]갤럭시S26U[512GB][SM-S948N]` = 0.125) **기준선은 올리지 않았다.**

### 수정

`rankItems()` 통과 조건을 `score > 0 && score >= minScore` 로 바꿨다.
`minScore: 0` 의 뜻은 그대로다 — 한 토큰이라도 걸리면 아무리 낮아도 남는다.
자세한 내용과 기존 테스트를 고친 부분은 `SEOSA_FIX_LOG.md` FIX-02 참고.

### 남은 것

최저가순 1위는 이제 핸드팩이 아니라 **키스킨(7,920원)** 이다 — 부속이 본품보다
싸서 그렇고 그건 F-05 의 몫이다. 거짓말이 하나 줄었을 뿐 «최저가 1위가 노트북»
이 된 것은 아니다.

## 확인했고 문제가 없던 것

측정 방법을 함께 적는다. «확인 안 함» 과 «확인했고 깨끗함» 을 구분하기 위해서다.

### 제휴 링크 — 443개 전부 통과
검색 22개 응답(359개) + today-drop(60) + `/api/init` 의 priceDrop·monthly·daily(24)
의 모든 `link` 를 `api/_affiliate.safeBuyLink` 에 그대로 통과시켰다.

- 빈 링크 **0**, 관문에 막힌 링크 **0**, `vendorItemId` 불일치 **0**

### SEO 크롤 건강 — 샘플 24개 전부 정상
사이트맵 인덱스 16개 파일 전부 200, 광고하는 URL **21,980개**(중복 0).
그중 24개를 균등 간격으로 뽑아 크롤러처럼 받아 봤다.

- 24/24 가 `200`, `noindex` 0건

### 입력 검증 — 35개 경계 입력에서 500 이 0건
빈 값·공백·기호만·200자·깨진 UTF-8·`'; DROP TABLE products;--`·경로 탈출
(`../../etc/passwd`, `%2e%2e%2f`)·`limit=-1/999999/abc`·널바이트 커서 등.

- `/sitemaps/products-0.xml`, `-99999.xml` → 404 + 빈 `<urlset>`

### 검색 결과 화면의 정렬·필터 — 전부 정확
`?q=무선 이어폰` 에서 직접 눌러 확인했다.

- 최저가순: 오름차순 ✓ (9,730 → …), 최고가순: 내림차순 ✓ (359,000 → …)
- `3만원 이하` → `?max=30000`, 실제 9,730~26,910원 ✓
- `3~10만원` → `?min=30000&max=100000`, 9건 30,830~69,750원 ✓ (칩 숫자와 일치)
- `10~50만원` → `?min=100000&max=500000`, 3건 179,530~359,000원 ✓ (칩 숫자와 일치)
- 같은 칩을 다시 누르면 해제되고 전체로 돌아온다 ✓

### 가격 기록 모달 — 그래프가 실제로 그려진다
카드 → «가격 기록» 으로 열고 `<canvas id="chart">` 의 픽셀을 직접 읽었다.
1250×560 중 **34.9% 가 그려져 있다**(빈 캔버스 아님). 판정 문구·신뢰도·
7/30/90/전체 탭·최저/평균/최고(39,000 / 42,074 / 42,900)·제휴 고지 모두 표시.

### 모바일 레이아웃 (375×812) — 가로 넘침 없음
`document.scrollWidth === clientWidth === 375`. 화면 밖으로 나간 요소들은 전부
가로 스크롤 레일(`.chips`, `nav.seo-quicklinks`, 카드 레일) 안이고 `overflow-x: auto`
라 닿을 수 있다. 데이터가 없는 섹션(외부 핫딜·FOR YOU)은 `display:none` 으로
스스로 숨어 빈 블록이 남지 않는다.

### 오늘 하락 데이터의 산술 정합성 — 60건 전부 일치
`dropAmount = previousPrice − currentPrice` 불일치 0, `dropPct` 오차(>0.15%p) 0,
음수·0원 0, `productId|vendorItemId` 중복 0.
최대 하락폭은 66.3%(59,000 → 19,900)인데, 저장 단계와 같은 상한
`MAX_PLAUSIBLE_DROP_PCT = 80%` 안이라 규칙대로다.

### XSS — 화면에 들어가는 외부 문자열이 전부 이스케이프된다
`public/index.html` 의 HTML 문자열 연결 95곳을 기계적으로 뽑아 하나씩 봤다.
상품명·몰 이름·검색어는 전부 `Fmt.esc`(`& < > " '`) 를 지나고, URL 은
`Fmt.safeUrl`(`^https?://`) 과 `Fmt.buyUrl`(제휴 관문) 을 지난다.
나머지는 코드가 만든 숫자·클래스명·SVG 좌표였다. `innerHTML` 에 외부 값을
직접 이어 붙이는 자리는 없었다. 검색어 반향(«"…" 큐레이션 중…»)도 `Fmt.esc` 를 거친다.

### SQL 인젝션 — 식별자는 화이트리스트, 값은 전부 파라미터
Neon 어댑터(`api/_neonpg.js`)가 테이블·컬럼명을 `IDENT` 정규식으로 검사하고
(`quoteIdent`, 실패하면 예외) 값은 `$n` 인자로 보낸다. 사용자 입력이 식별자
자리에 닿는 경로는 없었다.

### 보안 헤더
`X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`,
`Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`,
`Strict-Transport-Security: max-age=31536000; includeSubDomains` 전부 응답에 실린다.

### 순수 함수 크래시 스윕
16개 모듈의 공개 함수에 결측·NaN·서러게이트 반쪽·1만자 문자열·구조가 틀린 객체를

찾지 못했다(터진 것은 Symbol 이나 숫자를 배열 자리에 넣는 등 호출부가 만들지 않는 조합뿐).

### 중복 상품 — 설계상 의도
`10만원 이하 이어폰` 결과에 `제일이노텔 JM-205S …` 가 세 번 나오지만
