해석:
- v3.4의 개선(+15%p, 잘못된 카드 28%→13%)은 **수정에 쓰이지 않은 holdout에서도 재현**됐다. 개발 세트 개선(+22%p)보다 작다 — 개발 세트에 맞춘 효과가 일부 있었다는 뜻이다.
- **Hybrid(해시 임베딩)는 holdout에서 이득이 없다**(재현율·MRR 소폭 하락, 지연 +14ms). 개발 세트의 Recall@10 +0.008은 holdout에서 재현되지 않았다. 의미 임베딩(OpenAI 등)으로의 교체 효과는 측정하지 않았다.
- holdout 비-PASS 21건 중 실제 엔진 결함은 2건(H028 "그램 16" 화면 크기 파싱 누락으로 실재 상품 13건 미발견, H022 "S10 FE로"에 FE+ 혼입), 나머지는 정답이 "없음"인 문항(부재·모순·옵션 부재 9건)과 판정기 한계(오래된 기종 가격 하한, 노트북 사양의 '키보드', 'HEPA 필터', v2의 되묻기·장애 기준 부재)이다.

## 4. 실험별 결과

### 실험 A — 검색 정확성 (Recall@10·@20·MRR)
위 표. 정답 = 봉인 판정기가 코퍼스 전체에서 찾은 **현재가 표시 가능(10일 이내) 적격 상품**. 첫 검색 호출의 후보 목록 순위로 계산, Recall@K는 min(K, 정답 수)로 상한 보정.
- v3.3→v3.4: 개발 세트 Recall@10 0.791→0.827 (제외어 검색 반영·띄어쓴 앵커·가드로 상위 80행이 덜 오염됨), holdout은 동일(0.742).
- DB-first vs Hybrid: RRF 융합(w=1)은 MRR 0.860→0.901(개발 세트 중간 실행)로 올랐지만 최종 PASS 53→50, 잘못된 카드 40→45 → **기본값 expand**. holdout에서 expand는 이득 0.

### 실험 B — 잘못된 상품 제거 (주입)
fast-check가 실제 엔진에 유사 모델(Edge/Ultra/Plus/FE/Pro, 4개 계열 400회), 다른 용량 옵션(200회), 예산·배송비 초과(600회), 오래된 가격(250회), 액세서리(250회), 유선 제품(150회), 위험 URL(120회), 날조 ID(150회), 벡터 근접 변형(200회)을 주입 → 최종 카드에 하나도 나오지 않음(수정 후). 하이브리드 통합 테스트: S25 엣지·케이스·통신사가가 벡터 경로로 들어와도 카드가 되지 않음.

### 실험 C — 대화 연속성 (3턴 이상)
개발 세트 후속 문항 10개(3턴×9, 2턴→3턴): v3.3 3P/1F/1U/5R → v3.4 **7P/0F/1U/2R**. 고친 것: '게이밍' 3턴 유지(V057), "삼성 제품은 제외"(V060), 이어진 브랜드를 제외하면 조건 변경으로 처리. 속성 12(120회): 예산·브랜드 제외·중고 제외가 후속 턴에서 유지. holdout 후속 4문항: 2P/2R(H022에서 "S10 FE로" 정체성 누락 발견).

### 실험 E — 성능
- 서버 파이프라인 지연(로컬, GPT·네트워크 제외): 위 표. v3.4 DB-first가 v3.3보다 빠름(모순·오래된 가격 경로가 일찍 끝나고 가드가 후보를 줄임).
- pgvector 인덱스 (PGlite 77,737×256): 정확 스캔 p95 118.6ms → **HNSW(ef_search 100) p95 4.9ms, recall@10 0.992**; IVFFlat probes 40은 recall 0.957·p95 21.3ms. HNSW 빌드 301.7초(단일 스레드 WASM), 인덱스 99.4MB, 테이블+인덱스 210MB. `EXPLAIN ANALYZE`: `Index Scan using bench_hnsw … Order By: (embedding <=> …)`, shared hit 813.
- Neon 격리 브랜치(2,001행): HNSW recall 1.000, 왕복 포함 p50 71ms(서버 실행 ~1.1ms). 이 규모에선 플래너가 순차 스캔+정렬을 택함(정상) — 인덱스 효과는 대규모에서만.
- 새 인덱스로 인한 검색 악화: 없음(벡터 채널은 별도 DB·마감시간 1.5초, 키워드 질의 수 6.0→5.8로 감소).

### 실험 F — 독립 품질 평가 교차 검증

- 불일치의 대부분은 **v2가 가격 신선도를 보지 않는 것**(v3.3에서 v2 단독 66% vs 합의 33%), v2의 "N만원대" 해석 오류, 되묻기·장애·오래된 가격 기준 부재, 그리고 v3.4 판정기의 사양어 금지('NVMe', '백라이트 키보드') 같은 정답 조건 오류. 분류 기록: `reports/ai-v34-evaluation/review-v34-final.json`(개발 세트 24건: v3.4 판정기 오류 8, v2 오류 8, 확인 불가 4, 하한 경계 2, 남은 엔진 결함 3).
