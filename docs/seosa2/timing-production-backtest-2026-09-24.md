# 구매 타이밍 운영 데이터 백테스트 (2026-09-24 KST)

## 범위와 방법

운영 Supabase `products`와 `price_history`에 읽기 전용 `SELECT`만 실행했다. `scripts/backtest-timing.js`를 변경하지 않고, DB에서 추출한 최신 600개 쿠팡 카탈로그 키의 동일 옵션별 일별 가격 스냅샷을 로컬 테스트 어댑터로 공급해 기존 스크립트를 실행했다. 실 API 호출, DB 쓰기, 수집, 상품사 API 호출은 없었다.

기존 스크립트와 같은 기준을 썼다.

- `products`에서 최근 `collected_at` 순으로 `--limit × 3`개를 읽는다 (기본 `--limit 200`이면 600개).
- 가격 이력은 상품·몰·현재 `vendor_item_id`로 나누고 `sameVendorRows` 규칙을 적용한다. 같은 KST 날짜에 여러 행이 있으면 최저가 한 점만 남긴다.
- 백테스트는 `timing.analyze`의 walk-forward 결과를 집계한다. 예측 시점 뒤에 완전히 끝난 관측 창만 표본으로 쓴다.

## 운영 원장 범위

조회 시점의 운영 DB에는 쿠팡 카탈로그 22,973개와 전체 몰 가격 이력 154,027행이 있었다. 사용 가능한 가격 원장은 2026-07-14부터 2026-09-24까지 약 72일뿐이다. 동일 옵션의 최근 90일 일별 기록을 세면 다음과 같다.

| 지표 | 결과 |
|---|---:|
| 현재 쿠팡 상품 | 22,973 |
| 10일 이상 기록이 있는 상품 | 1,305 |
| 45일 이상 기록이 있는 상품 | 16 |
| 60일 이상 기록이 있는 상품 | 0 |
| 90일 이상 기록이 있는 상품 | 0 |
| 상품별 기록 일수 중앙값 | 2일 |
| 최장 기록 | 53일 |
| 비정상 가격(0 이하)이 있는 계열 | 0 |

따라서 현재 원장은 90일을 채우지 못했다. 아래의 90일 백분위는 “최근 90일 구간에 실제로 관측된 값 중”의 백분위이며, 90일 연속 기록을 뜻하지 않는다.

## 기본 백테스트 (`horizon=14`, `min-days=45`, `limit=200`)

기본 실행이 보는 최신 600개 상품 중 자격을 갖춘 계열은 2개였다. 두 계열 모두 14일 전망 평가에 필요한 최소 20개 walk-forward 표본에 못 미쳤다.

| 상품 계열 | 동일 옵션 관측 | 기간 | 현재가 | 90일 구간 백분위 | 14일 검증 |
|---|---:|---|---:|---:|---|
| 크앤비 재사용 자석 물풍선 | 45일 (46행, 같은 날 중복 1일) | 2026-07-28–2026-09-24 | 11,300원 | 하위 2% (관측 45일) | 14개 평가일, 최소 20일 미달 |
| 내셔널지오그래픽 스마트폰 방수팩 | 46일 (46행) | 2026-07-27–2026-09-24 | 12,890원 | 가격 변동 0%, 백분위 없음 | 18개 평가일, 최소 20일 미달 |

기본 실행 집계는 `productsEvaluated=2`, `verdicts.insufficient=2`, 점수화 가능한 `samples=0`, Brier 점수·기준 모델·skill·구간 적중률 모두 `null`이다. 두 상품 모두 노트북·휴대 전자제품 본체의 가격 패턴을 대표하지 않는다.

## 보조 기간 비교

7일을 탐색적으로 실행하면 52개 평가 표본, Brier 0.038, 기준 모델 Brier 0.038, skill 0, 예측 구간 포함률 0.96이 나왔다. 권고 결정은 0건이라 결정 적중률은 계산할 수 없다. 기본 예측 기간은 14일이며, 7일 결과도 기준 모델보다 낫지 않고 상품군이 두 개뿐이어서 성능 통과 근거로 쓰지 않는다.

30일에서는 평가 표본이 0개라 점수를 낼 수 없었다.

## 품질·누출·불확실성

- 동일 옵션 이력만 사용했다. 잘못된 옵션의 낮은 가격이 다른 옵션 계열에 섞이지 않는다.
- 두 계열 모두 0 이하 가격은 없었다. 물풍선 계열은 46행 중 한 KST 날짜에 중복 기록이 있었고, 기존 일별 집계 규칙대로 한 점으로 접었다.
- 최신 600개에서 자격 계열 두 개의 관측일은 약 59–60일 범위에 45–46일이다. 원장에 날짜 누락이 있어 관측 표본이 완전한 연속 시계열은 아니다.
- 누출 방지 코드 경로는 오프라인 테스트의 17개 walk-forward 시점과 미완료 미래 창 검사에서 통과했다. 운영 14일 백테스트는 표본 부족으로 성능 자체를 검증하지 못했다.
- 14일·30일 예측 성능, 전자제품 상품군별 성능, 예측 권고 적중률은 현재 데이터로 판단할 수 없다. UI에 미래 가격을 확정적으로 쓰거나 “기다리면 내려간다”고 단정하지 않는다.

## 판단과 다음 기준

**현재 운영 데이터만으로는 #72의 예측을 공개하거나 PR을 병합할 수 없다.** API는 기존 규칙대로 표본 부족을 `insufficient`/불확실로 표시해야 한다. 다시 검증할 때는 원장 최소 90일을 확보하고, 여러 상품군에서 14일 완결 관측 창을 상품별 20개 이상 모은 뒤 기준 모델보다 나은 Brier skill, 권고가 나온 경우의 적중률, 예측 구간 포함률을 함께 확인한다. 그 전까지 구매 타이밍 화면은 운영 노출을 보류한다.
