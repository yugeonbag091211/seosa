# SEOSA 사용자 테스트 프로토콜

> 이 문서는 **혼자 읽고 끝내는 문서가 아니라, 옆에 두고 그대로 진행하는 대본**이다.
> 진행자(박유건)가 읽을 말은 「」 안에 그대로 적혀 있다. 바꾸지 말고 그대로 읽는다.
>
> 마지막 업데이트: 2026-08-30 (2차 UI 검증 직후)

---

## 0. 이 테스트로 알고 싶은 것

기존 피드백은 이것 하나였다.

> "일단 UI가 너무 Claude 스러워서 거부감이 생김. 그래서 아예 클릭조차 해보지 않았음."

리디자인을 했지만 **아직 아무도 새 화면을 보고 평가하지 않았다.**
따라서 지금 상태는 「개선됨」이 아니라 **「개선됐다는 가설」**이다.

이 테스트가 답해야 하는 질문은 넷이다.

| # | 질문 | 답이 되는 관찰 |
|---|---|---|
| Q1 | 처음 본 사람이 **무슨 사이트인지** 아는가 | 5초 뒤 자기 말로 설명할 수 있는가 |
| Q2 | **첫 클릭**이 막히지 않는가 | 5초 안에 손이 어디로 가는가 |
| Q3 | **가격이 좋은지** 판단할 수 있는가 | 근거를 말하는가, 감으로 말하는가 |
| Q4 | **AI를 스스로 발견**하는가 | 안내 없이 찾아내는가 |

## 1. 준비

### 진행자가 준비할 것
- [ ] 노트북 1대 (데스크톱 테스트) + 본인 휴대폰 (모바일 테스트)
- [ ] **로그인하지 않은 상태**의 새 브라우저 창 (시크릿 창)
- [ ] localStorage 비우기 — 위시리스트·최근 검색이 남아 있으면 첫인상이 오염된다
- [ ] 이 문서 인쇄본 또는 다른 기기에 띄워 둘 것
- [ ] 타이머 (휴대폰 스톱워치)
- [ ] 녹음 (참가자 동의 후). 없으면 §6 기록지에 손으로 적는다

### 참가자
- **4~6명이면 충분하다.** 5명이면 사용성 문제의 약 80%가 나온다.
- 조건: 온라인 쇼핑을 해 본 사람. **SEOSA를 처음 보는 사람.**
- 가족·친구도 괜찮다. 다만 "잘 만들었다고 말해 줘야 할 것 같은" 사람은 첫인상 테스트에 쓰지 않는다.
- 최소 2명은 **휴대폰으로** 테스트한다. 실사용의 대부분이 모바일이다.

### 절대 하지 말 것
- ❌ 시작 전에 서비스를 설명하지 않는다. (설명하는 순간 첫인상 테스트가 사라진다)
- ❌ 「Claude 느낌 없앴는데 어때요?」 라고 묻지 않는다. **답이 편향된다.**
- ❌ 참가자가 막혔을 때 곧바로 도와주지 않는다. **막히는 지점이 데이터다.**
- ❌ 「여기 눌러보세요」 라고 유도하지 않는다.
- ❌ 참가자가 틀렸다고 말하지 않는다. 틀리는 건 화면 잘못이다.

### 시작할 때 읽을 말

> 「오늘 테스트하는 건 ○○님이 아니라 이 화면이에요. 잘하고 못하고가 없어요.
> 헷갈리거나 이상하면 그게 제일 도움이 되는 정보예요.
> 하시는 동안 **머릿속 생각을 소리 내서** 말해 주시면 좋아요.
> 예를 들면 '이게 뭐지', '여기 눌러볼까' 같은 거요.
> 제가 중간에 대답을 못 해도 서운해하지 마세요. 일부러 그러는 거예요.」

## 2. Test 1 — 첫인상 (5초)

**목적**: 이 사이트가 무엇인지 5초 안에 전달되는가

**방법**
1. 화면을 참가자에게 **보여주지 않은 채** 홈을 띄워 둔다
2. 「지금부터 화면을 5초만 보여드릴게요. 그냥 보시면 돼요.」
3. 5초 노출 → **화면을 가린다** (노트북 덮기 / 탭 전환)
4. 질문:

> 「방금 본 거, **뭐 하는 사이트 같았어요?**」

5. 이어서:

> 「기억나는 거 아무거나 말해 주세요.」

**기록할 것**
- [ ] 참가자가 쓴 **단어 그대로** 적는다 (요약하지 말 것)
- [ ] "가격", "기록", "쇼핑", "비교", "싸다" 중 나온 단어에 표시
- [ ] "AI"를 먼저 말했는가? ← **말했다면 문제다.** AI가 상품보다 먼저 읽혔다는 뜻

**통과 기준**
> 「가격(싼 거 / 할인 / 가격 비교) 관련 쇼핑 사이트」 취지의 답이 나오면 통과.
> 「모르겠다」 / 「AI 서비스」 / 「블로그·뉴스」 → **Critical**

---

## 3. Test 2 — 첫 행동

**목적**: 첫 클릭이 명확한가

1. 화면을 다시 보여준다 (이번엔 계속 열어 둠)
2. 「여기서 **뭘 눌러볼 것 같아요?** 아직 누르지는 마시고 손가락으로만 가리켜 주세요.」
3. 가리킨 곳을 적는다
4. 「왜 거기예요?」
5. 「그럼 눌러보세요.」 → 기대와 실제가 맞았는지 관찰

**기록할 것**
- [ ] 처음 가리킨 요소 (검색창 / 카테고리 / 상품 행 / AI / 기타)
- [ ] 누른 뒤 표정·반응 ("어 이게 나오네" / "어라")
- [ ] **기대와 결과가 달랐는가**

**통과 기준**
> 검색창·카테고리·상품 중 하나를 가리키면 통과.
> 한참 훑기만 하고 못 고르면 **High**

---

## 4. Test 3 — 상품 탐색

**목적**: 실제로 상품을 찾아낼 수 있는가

> 「**3만원 이하로 살 만한 물건을 하나 찾아보세요.**
> 다 찾으시면 '찾았다'고 말해 주세요.」

*(주의: 원래 안은 "30만원 이하 노트북"이었는데, 현재 수집 데이터는 생활용품이
많아 결과가 빈약할 수 있다. 시연 직전에 실제 데이터를 보고 금액을 정할 것.)*

**관찰만 하고 절대 돕지 않는다.**

**기록할 것**
- [ ] 검색을 쓰는가 / 카테고리를 쓰는가 / 그냥 스크롤하는가
- [ ] 검색창을 **몇 초 만에** 찾는가
- [ ] 검색어로 무엇을 입력하는가 (자동완성을 쓰는가)
- [ ] 결과에서 가격을 비교하는가
- [ ] 필터·정렬을 건드리는가 (모바일은 「상세 필터」를 펴는가)
- [ ] 완료까지 걸린 시간
- [ ] **포기했는가** ← 포기가 가장 중요한 데이터

**통과 기준**
> 2분 안에 상품 하나를 지목하면 통과. 3분을 넘기거나 포기하면 **High**

---

## 5. Test 4 — 가격 판단

**목적**: SEOSA의 핵심 가치 — "이 가격이 좋은가"에 답할 수 있는가

1. 진행자가 원장(가격 하락 목록)의 **한 행을 지정**한다
2. 「이 상품, **지금 가격이 좋은 편인지 판단해 보세요.**
   어디를 보고 그렇게 생각했는지도 같이 말해 주세요.」

**기록할 것**
- [ ] 어디를 보는가: 낙폭 % / 이전 기록가 / 「기록상 최저」 / 가격 추이 그래프 / 신뢰도
- [ ] **가격 추이 모달을 여는가** ← 안 열면 행이 클릭 가능하다는 걸 모르는 것
- [ ] 판단 근거를 말하는가, "그냥 싸 보여서"라고 하는가
- [ ] 「기록상 최저」의 뜻을 이해하는가

**통과 기준**
> 화면의 데이터(평균 대비 / 이전가 / 그래프) 중 하나를 근거로 대면 통과.
> 근거 없이 감으로만 답하면 **High** — 가격 UI가 일을 못 하고 있다는 뜻

---

## 6. Test 5 — AI 발견 (안내 금지)

**목적**: 설명 없이 AI Concierge를 발견하는가

> 「이 사이트에서 **할 수 있는 게 또 뭐가 있을 것 같아요?**
> 화면을 둘러보면서 말해 주세요.」

- AI를 언급하지 않으면 **끝까지 말하지 않는다**
- 30초 뒤에도 못 찾으면 그것이 결과다. 기록하고 넘어간다

**기록할 것**
- [ ] AI를 발견했는가 (예/아니오)
- [ ] 발견했다면 **어느 요소로** 발견했는가
      (우하단 앵커 / 「조건으로 찾고 싶다면」 텍스트 / 검색 결과의 맥락 링크 / ⋯ 메뉴)
- [ ] 발견까지 걸린 시간
- [ ] 「저게 뭐예요?」 라고 묻는가, 아니면 무시하는가

**통과 기준**
> 30초 안에 발견 → 통과. 못 찾으면 **Medium** (발견성 부족).
> 반대로 **처음부터 AI만 눈에 띄었다고 하면 Medium** (상품보다 먼저 읽힘)

## 7. Test 6 — AI 사용

**목적**: AI가 쇼핑 맥락 안에서 쓰이는가

> 「아까 보신 그 상품, **지금 사도 괜찮은지 물어보세요.**」

**기록할 것**
- [ ] AI 진입점을 스스로 찾는가
- [ ] 무엇이라고 입력하는가 (**입력한 문장 그대로** 적는다)
- [ ] 로그인 요구를 만났을 때 반응 ← 이탈 지점일 가능성 높음
- [ ] 답변을 읽는가, 스크롤로 넘기는가
- [ ] 후속 질문 칩을 누르는가
- [ ] 답변이 도움이 됐다고 느끼는가

> ⚠️ **알아둘 것**: AI는 로그인해야 쓸 수 있다. 참가자에게 계정이 없으면
> 이 테스트는 「로그인 벽에서 멈춤」으로 기록하고 끝낸다. 그 자체가 결과다.
> 억지로 진행자 계정으로 로그인시키면 실제 사용자 경험이 아니다.

## 8. 마무리 질문 (테스트 후)

순서대로 묻는다. **답을 요약하지 말고 그대로 받아 적는다.**

1. 첫인상이 어땠나요?
2. 이 사이트는 무엇을 하는 곳 같았나요?
3. 처음에 무엇을 누르고 싶었나요?
4. 가장 이해하기 어려웠던 부분은 어디였나요?
5. 가장 불필요해 보였던 부분은요?
6. 검색은 쉽게 찾으셨나요?
7. 가격 정보는 이해하기 쉬웠나요?
8. AI가 있다는 걸 발견하셨나요?
9. AI가 너무 튄다고 느끼셨나요?
10. 기존에 쓰시던 쇼핑몰이랑 다른 점이 있다면 뭘까요?

**마지막에 딱 하나만 더:**

> 「이 사이트, **다시 올 것 같으세요?** 온다면 어떤 때에 올 것 같아요?」

이 답이 제품의 존재 이유에 가장 가깝다.

### 물으면 안 되는 질문 (편향 유발)
- ❌ 「디자인 깔끔하죠?」
- ❌ 「Claude 같지 않죠?」
- ❌ 「AI 기능 좋지 않아요?」
- ❌ 「가격 기록해 주는 거 유용하죠?」
- ❌ 「여기 이렇게 만든 게 나은 것 같지 않아요?」

## 10. 심각도 판정 기준

| 등급 | 정의 | 조치 |
|---|---|---|
| **Critical** | 서비스 목적을 이해하지 못함 / 아무것도 못 함 | 즉시 수정 |
| **High** | 검색·상품 탐색·가격 판단 중 하나가 막힘 | 즉시 수정 |
| **Medium** | 특정 UI가 혼란스럽지만 우회 가능 | 2명 이상에서 반복되면 수정 |
| **Low** | 개인 취향 | **기록만 한다. 고치지 않는다** |

### 취향과 사용성을 가르는 법

| 발언 | 분류 | 이유 |
|---|---|---|
| 「어디를 눌러야 할지 모르겠어요」 | **사용성** | 목표 달성이 막힘 |
| 「이게 무슨 뜻인지 모르겠어요」 | **사용성** | 이해 실패 |
| 「글씨가 너무 작아서 안 보여요」 | **사용성** | 읽기 실패 |
| 「저는 파란색이 좋아요」 | 취향 | 목표와 무관 |
| 「좀 심심하네요」 | 취향 | 단, **3명 이상**이 말하면 재검토 |
| 「촌스러워요」 | 취향 | 단, 이유를 물어 사용성 문제가 숨어 있는지 확인 |

> **한 명의 취향을 그대로 반영하지 않는다.**
> 같은 문제가 **2명 이상**에게서 나오면 그때 패턴이다.

## 12. 이번 테스트에서 특히 확인할 것 (2차 검증에서 나온 가설)

내부 검사에서 고친 것들이 **실제로 효과가 있는지**는 아직 모른다.
아래는 각 수정의 가설이고, 위 테스트가 검증한다.

| 수정 | 가설 | 검증되는 항목 |
|---|---|---|
| 히어로 → 「가격 원장」 바 | 5초 안에 무슨 사이트인지 전달된다 | **T1** |
| 검색을 헤더에 상주 | 검색을 찾는 데 5초 이상 걸리지 않는다 | **T3** |
| 원장 행에 점선 밑줄 + 안내 문구 | 행이 클릭 가능하다는 걸 안다 | **T4** (모달 여는가) |
| 카드 가격을 상품명보다 크게 | 가격을 먼저 본다 | **T4** |
| AI 앵커 축소 + 스크롤 시 접힘 | AI가 상품보다 먼저 읽히지 않는다 | **T1, T5** |
| 「기록상 최저」 색 낮춤 | 낙폭 %와 경쟁하지 않는다 | **T4** |
| 몰별 비교에 안내 문구 추가 | 다른 상품임을 알아챈다 | 별도 관찰 (아래) |

### 추가 관찰 — 몰별 비교 (Critical 위험)

현재 몰별 비교는 **상품명 앞 3단어로 재검색**해서 몰마다 가장 싼 것을 모은다.
그래서 **전혀 다른 상품이 섞인다.** 실측 예:

```
"모두샵 소가죽 남자 슬림 반지갑" 비교 결과
  오늘의집   남자샌들 아쿠아 스포츠샌들     26,900원  ← 반지갑이 아님
  쿠팡       소가죽 크로스백               76,900원  ← 반지갑이 아님
```

UI에는 안내 문구를 넣었지만 **근본 원인은 백엔드 매칭**이다.
테스트 중 참가자에게 몰별 비교를 열어 보게 하고:

> 「이 표, 어떻게 보이세요?」

- 참가자가 **다른 상품임을 알아채면** → 안내 문구가 작동한 것
- **못 알아채고 "이게 더 싸네"라고 하면** → **Critical**, 기능을 내려야 한다

## 13. 테스트가 끝난 뒤

1. 기록지를 §11 집계표로 옮긴다
2. **2명 이상**에게서 나온 문제만 수정 후보로 올린다
3. Critical/High를 먼저 고친다
4. 고친 뒤 **같은 시나리오로 새 참가자 3명**에게 다시 돌린다
   (같은 사람에게 다시 하면 이미 학습해서 의미가 없다)
5. 결과를 `docs/ux-redesign-log.md` 에 이어 적는다

> **테스트 결과가 나오기 전까지 「UX가 개선됐다」고 쓰지 않는다.**
> 그전까지는 「내부 평가상 개선됐다」가 정확한 표현이다.
