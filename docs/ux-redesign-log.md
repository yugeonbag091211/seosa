# SEOSA UI/UX 리디자인 기록

> 의사결정의 근거와 실측치를 남긴다. 포트폴리오·면접에서 "왜 그렇게 했는가"에
> 답할 수 있어야 하므로, **결과보다 판단 과정**을 적는다.
>
> 기간: 2026-08-29 ~ 2026-08-30

## Problem

SEOSA는 가격 원장 + AI 컨시어지를 갖춘 쇼핑 큐레이션 서비스다.
백엔드(가격 수집·Decision/Deal Engine·Confidence·AI 파이프라인)는 완성됐고
테스트 2,588건이 통과하는 상태였다.

그런데 **아무도 쓰지 않았다.**

## User Feedback (n=1, 2026-08-29 이전)

> "일단 UI가 너무 Claude 스러워서 거부감이 생김.
> 그래서 아예 클릭조차 해보지 않았음."

이 한 문장에 세 가지가 들어 있다.

1. **거부감** — 감정 반응이 클릭 이전에 발생했다
2. **특정 AI 제품 연상** — 브랜드 혼동
3. **행동 0** — 기능이 아무리 좋아도 도달하지 못했다

기능 문제가 아니라 **첫인상에서 이탈**하는 문제다.

## Hypothesis

> **H1** 「Claude처럼 보이지 않게」는 목표가 아니다.
> 목표는 「SEOSA처럼 보이게」다. 서비스의 실제 성격에서 시각 언어를 도출하면
> 특정 서비스를 닮지 않으면서 평범한 쇼핑몰도 되지 않는다.

> **H2** SEOSA의 실제 정체성은 「예쁜 큐레이션」이 아니라
> **「매일 가격을 기록하는 원장」**이다. 카드가 아니라 행, 면이 아니라 규칙선,
> 그리고 **관측일을 항상 밝히는 것**이 고유성이 된다.

> **H3** 첫 화면에서 상품에 닿는 거리를 줄이면 첫 클릭률이 오른다.

> **H4** 색의 예산은 데이터가 갖는다. 상시 의미색이 하락(초록)·상승(빨강)
> 둘뿐이므로, 세 번째 채도 높은 브랜드색을 컨트롤에 뿌리면 가격 신호가 묻힌다.

## Design — 「가격 원장(Ledger)」

### 원칙 7가지
1. 기록이 곧 정체성 — 관측일을 항상 밝힌다
2. 카드가 아니라 행 — 규칙선이 구조를 만든다
3. 색은 데이터의 것 — 크롬은 무채색
4. 상품이 먼저, 설명은 나중
5. 숫자는 숫자답게 — tabular, 큰 대비, 델타 동반
6. AI는 맥락 안에 — 상품보다 먼저 읽히지 않는다
7. 과장하지 않는다 — 근거 있는 문장만

### 근거가 있는 개별 결정

| 결정 | 이유 (취향 아님) |
|---|---|
| 표면 `#FCFCFB` → `#FFFFFF` | 쿠팡 상품 사진이 흰 배경 누끼로 온다. 웜 페이퍼 위에서는 사진이 페이지보다 밝은 사각형으로 떠 보였다 |
| 웜 그레이 → 쿨 뉴트럴 | 웜 그레이는 종이·서적의 색이다. 이 제품이 다루는 건 매일 갱신되는 관측 기록이다 |
| 세리프 전면 제거 | 에디토리얼 연상의 절반이 여기서 왔다 |
| 모노를 관측일·행번호에만 | 가격에 모노를 쓰면 "영수증·터미널"로 읽힌다. 한글 글리프가 없어 조용히 폰트가 바뀌는 문제도 있었다 |
| 본문 Pretendard | 한글 상품명 2줄 클램프에 더 들어가고, 숫자 tabular가 정확해 가격이 표처럼 줄맞춤된다 |
| radius 4px 이하 | 전부 알약이면 형태가 아무것도 구분해 주지 못한다. 완전한 원은 "셀 수 있는 것"에만 |
| 브랜드색 = 황동, 컨트롤 금지 | 초록/빨강과 충돌하지 않고, 파랑/보라(AI 클리셰)도 아님. 원장·연감의 색 |
| 검색을 헤더로 | 발견성↑(모든 화면 상주) · 지배력↓(헤더 요소 하나) · 히어로 확보 |

## 3차 감사 (2026-08-30) — 가격비교 서비스로서의 데이터 검증

1·2차는 **화면**을 봤다. 3차는 처음으로 **가격비교 서비스에 필요한 데이터가
실제로 있는가**를 봤다. 여기서 가장 큰 문제들이 나왔다.

### 상품 모델의 실제 컬럼

```
product_id · mall · mall_label · keyword · title · lprice · oprice
save_pct · link · image · item_id · vendor_item_id · collected_at
```

**없는 것**: `shipping_fee` · `availability` · `brand` · `mpn/gtin` ·
`category` · `option_label` · `seller` · `unit_price` · `rating`

→ 총비용 기준 최저가, 동일상품 매칭(1·2순위), 단위가격, 판매처 신뢰도를
**구조적으로 만족할 수 없다.**

### 발견한 것

| # | 문제 | 증거 | 조치 |
|---|---|---|---|
| C1 | **배송 데이터가 계층 하나에서 통째로 버려짐** | `_coupang.js`가 `isRocket`/`isFreeShipping`을 주석까지 달아 추출 → `_shop.js:118`이 항목을 새 객체로 만들며 **둘 다 누락**. 실측 검색 20건 중 배송 데이터 **0건**. 배송 필터 UI는 데이터가 있어야 뜨므로 **한 번도 뜬 적 없음** | **수정** (2줄) |
| C2 | **"역대 최저가" 과장** | 최소 **3일치** 기록으로 "역대"를 주장. 실측 20건 중 **10건**에 배지 | **수정** — "N일 기록 중 최저", 문턱 3→7일 |
| C3 | **"평균 대비 -77%"** | 서로 다른 18개 상품의 평균 대비 최솟값. 사용자는 "평소보다 77% 싸다"로 읽음 | **수정** — 「가격대 9,900~179,000원」으로 교체 |
| C4 | 동일상품 매칭이 상품명 앞 3단어 | 반지갑 → 샌들/크로스백 | 백엔드, 미수정 (UI 문구만 2차에서 완화) |
| H3 | SEO structured data **0건** | Product/Offer JSON-LD 없음 | **수정** — WebSite+SearchAction+Organization |

### C1이 왜 오래 살아남았나 (기록해 둘 가치가 있는 실패)

- `_coupang.js`에는 이 필드를 왜 넘기는지 설명하는 **20줄짜리 주석**이 있었다
- `scripts/test-filters.js`는 배송 필터 로직을 **정상적으로 테스트**하고 통과했다
- 그런데 그 스크립트는 `npm test` 체인 **밖**이었고, 테스트는 필터 함수에
  객체를 직접 넘겨서 검사했기 때문에 **데이터가 실제로 도착하는지는 아무도 확인하지 않았다**

> 단위 테스트가 통과하는데 기능이 죽어 있을 수 있다.
> 계층 사이에서 객체를 **다시 만드는 코드**가 있으면 거기가 필드가 사라지는 자리다.

### C4 동일상품 매칭 — 왜 제목에 의존할 수밖에 없는가

지시는 "GTIN → MPN → 브랜드+모델 → 제목 유사도" 순으로 매칭하라고 했다.
그래서 **API 가 이미 주는데 우리가 버리고 있는지**부터 확인했다.

```
쿠팡 검색 API 가 주는 것
  productId · productName · productPrice · productUrl · productImage
  discountPrice · isRocket · isFreeShipping

ADPICK 이 주는 것
  title · price · commissionlink · photo · cp_code · cp_name
```

**둘 다 GTIN·MPN·브랜드·모델·재고를 주지 않는다.**
버려지고 있던 것은 배송 두 필드뿐이었고 그건 복구했다.
→ DB 컬럼을 추가해도 **채울 데이터 소스가 없다.** migration 을 제안하는 것
자체가 의미 없다. 매칭은 제목에 의존할 수밖에 없고, 그렇다면 답은 하나다:
**보수적으로 판정하고, 확신이 없으면 비교하지 않는다.**

#### 예전 규칙이 실패한 이유

```js
need = Math.min(2, keyTokens.length)   // 핵심 토큰 2개만 맞으면 통과
```

```
원본  "모두샵 소가죽 남자 슬림 반지갑 선물상자 MARLMS162"
통과  "OMT 소가죽 남자샌들 …"          ← 소가죽 + 남자 = 2개
통과  "남자들천연 소가죽 크로스백 …"    ← 소가죽 + 남자 = 2개
표시  "최대 절약 50,000원"
```

#### 새 규칙

| 등급 | 조건 | 처리 |
|---|---|---|
| strong | 모델코드 일치 **또는** 핵심 토큰 70%+ | 비교 · "최대 절약" 사용 가능 |
| fair | 핵심 토큰 50%+ | 비교 · **"가격 차이"만**, "같은 상품이 아닐 수 있어요" |
| weak | 그 미만, 또는 일치 토큰 2개 미만 | **제외** |

모델코드는 제목에서 뽑는다 — 영문+숫자가 섞인 4자 이상 토큰
(`marlms162`, `nessd013682z`, `sms938n`). 순수 숫자는 용량·사이즈일 때가
많아 제외한다.

#### 검증 (실제 시세판 상품 4종, 캐시된 후보로 채점)

| 상품 | 후보 | strong | fair | weak | 결과 |

### 가격 이상치 — 매칭이 맞아도 가격이 틀릴 수 있다

매칭을 조인 뒤 실제 화면에서 이것이 나왔다.

```
원본  "LG전자 코드제로 R5 로봇청소기 R585WKA"
알리  "[해외] LG 전자 코드제로 R5 R585WKA, Rowenta…"     7,870원  ← 최저가·초록 강조
쿠팡  "LG전자 코드제로 R5 로봇청소기"                   724,720원
요약  "가격 차이 716,850원"
```

7,870원짜리 LG 로봇청소기는 없다. 제목에 모델코드가 있어서 게이트를
통과했다 — **매칭이 맞아도 가격 자체가 틀릴 수 있다.**

수정:
- 중앙값의 35% 미만인 행은 **최저가·가격차이 계산에서 제외**
- 그 행은 지우지 않고 "가격 확인 필요" + 취소선으로 표시 (존재는 사실이므로)
- 뺐다는 사실을 문구로 밝힘
- 초록 강조(`tr.best`)를 **인덱스 기준 → 실제 최저가 기준**으로
  (예전에는 의심 행이 1행이라 그 행이 "가장 좋은 선택"으로 강조됐다)

결과: `이 중 최저 7,870원 · 가격 차이 716,850원` → `이 중 최저 724,720원`

### 이번에 배운 것 — 테스트가 통과하는데 기능이 죽어 있던 이유

`scripts/test-filters.js` 는 배송 필터를 65케이스로 정상 테스트하고 통과했다.
그런데 그 테스트는 **필터 함수에 객체를 직접 넘겨** 검사했다. 즉
"필터가 맞게 거르는가"는 봤지만 **"그 데이터가 실제로 도착하는가"는 아무도
보지 않았다.** 게다가 그 스크립트는 `npm test` 체인 밖이었다.

> 계층 사이에서 객체를 **다시 만드는 코드**가 있으면 거기가 필드가 사라지는 자리다.
> 단위 테스트는 그 자리를 절대 못 본다.

그래서 이 테스트를 체인에 넣었다. 같은 종류의 사고를 다음에는 잡는다.

## 이 프로젝트에서 배운 것 (기록용)

1. **"AI처럼 보인다"는 색 문제가 아니라 조합 문제였다.** 다섯 요소를 동시에
   바꿔야 했고, 하나만 바꿨다면 아무것도 달라지지 않았을 것이다.
2. **내가 만든 디자인을 내가 측정할 수는 있어도 평가할 수는 없다.**
   측정(대비비·픽셀·개수)은 객관적이지만 "좋아 보인다"는 아니다.
3. **리디자인 중에 내가 새 버그를 만들었다** (`.why-line` 색 방향).
   "평균보다 높아요"가 초록으로 나갔다 — 색이 글자와 반대되는 말을 하면
   사용자는 색을 먼저 믿는다. 자기 작업을 스스로 검사해야 하는 이유다.
4. **가장 심각한 문제는 디자인이 아니라 데이터였다** (몰별 비교 매칭).
   UI를 아무리 다듬어도 틀린 데이터를 보여주면 신뢰를 잃는다.
   UI가 할 수 있는 최선은 **데이터보다 더 많이 주장하지 않는 것**이었다.

## 남긴 예외 (고치지 않기로 한 것과 이유)

1. **문장 안의 정책 링크 32px** — WCAG 2.5.5 의 "Inline" 예외.
   줄 높이가 링크가 아닌 글자에 묶여 있어서 44px 을 주면 문단이 벌어진다.
   하한(2.5.8 의 24px)은 넘긴다.
2. **알림 체크박스 24x24** — 감싼 줄(`.alert-check`)이 44px 이라 실제로
   누르는 면적은 44px 이다. 체크박스 자체를 키우면 폼이 뭉개진다.
3. **하트·공유는 보이는 크기 26~30px 유지** — 상품 사진 위에 떠 있어서
   눈에 보이는 크기를 44px 로 키우면 167px 짜리 사진의 절반을 덮는다.
   투명 `::after` 로 **눌리는 면적만** 44x44 로 넓혔고, 두 버튼의 판정
   영역이 겹치지 않도록 공유를 8px 밀었다(중심 간격 실측 47px).

| P7 | 여백이 좁다 | 섹션 56px · 그리드 24px · 섹션머리 18px — 전부 비슷해서 위계가 없음 |
| P8 | 타이포가 평평 | 섹션 제목 1.18rem vs 카드 가격 1.32rem |
| P9 | 검색 결과 첫 화면에 **상자 22개** | 정렬 5 · 몰 3 · 가격 6 · 신뢰도 5 · 배송 2 → 첫 상품 y=470 |

## 무엇을 했는가

**1. 카드에서 겹을 걷어냈다**
- 사진 위 몰 배지 제거 → 판매처는 `.mall-line` 한 곳
- `.cmp`(정가 대비 N원 저렴) 제거 → 할인은 `-N%` 하나로
- `.atl-badge`(N일 최저)를 사진 위 → 가격 아래 텍스트로 이동
- `.pchg` 배경 칩 제거 → 색은 글자에만
- 변동에 관한 표시를 `.pmove` 한 줄로 모음 (비어 있어도 자리 유지 → 그리드 정렬)

**2. 지시 5의 순서를 실제로 적용**
`가격 → 가격 변동 → 상품명 → 판매처(+관측일) → 배송 → 신뢰도`
상품명이 판매처보다 위인 이유: 같은 사진 다른 용량이 흔해서, 가격 다음 질문이
"어디서"가 아니라 "이게 뭔데"다.

**3. 상자를 여백으로 바꿨다**
- 카드 테두리·썸네일 구분선 제거, 사진을 `--surface` 면에 앉힘
- 섹션 사이 규칙선 제거, 간격 56 → 96px
- 카드 글의 좌우 패딩 0 → 사진 왼쪽 끝과 글 왼쪽 끝이 같은 기준선

**4. 타이포 위계를 벌렸다**
섹션 제목 1.18 → 2.05rem, 카드 가격 1.32 → 1.62rem, 원장 현재가 1.0 → 1.16rem

**5. 채운 검정 덩어리를 걷어냈다**
`이 키워드 더보기`(알약) · 원장 행의 `구매`(알약) · 선택된 키워드 칩(채움) →
전부 텍스트/밑줄로. 키워드 칩은 상단 카테고리 내비와 **같은 언어**로 통일했다
(같은 일을 하는 컨트롤이 두 가지 모양이면 다른 것으로 읽힌다).

**6. 검색 결과: 도구보다 결과를 먼저**
상세 필터를 데스크톱에서도 기본 접힘으로. 정렬·몰만 남기고 나머지는
「상세 필터」 뒤로. 모바일 정렬 줄은 접지 말고 가로로 흘림(`.catnav`와 같은 방법).
→ 첫 상품 **y=470 → 318**(데스크톱), **437 → 388**(모바일)

## 이번에 드러난 4차의 측정 허점

4차 보고서에 「44px 미만 = 2종」이라고 적었는데, 그 측정은 **홈 화면에서만**
했다. 검색 결과 화면에만 있는 `.filter-btn`(41x27) · `.facet-btn` ·
`.facet-toggle`(90x38)은 화면에 없어서 세어지지 않았다.

더 나쁜 것은 4차 수정이 만든 문제였다. 검색 실행 버튼을 40 → 44px 실물
버튼으로 키웠더니, 375px 헤더에서 검색칸 125px 중 44px 을 버튼이 가져가
**입력 자리가 57px**, 320px 에서는 **12px** 이 됐다. 접근성 규칙이 이 사이트에서
가장 중요한 컨트롤을 눌러 버린 것이다.

고친 방법은 찜·공유에 이미 쓰던 것이다 — 아이콘은 30px, 투명 `::after` 로
판정만 44x44. 둘 다 지킬 수 있는데 한쪽을 포기했던 셈이다.

**교훈: 측정 범위를 밝히지 않은 「통과」는 통과가 아니다.**

# 6차 — Apple UX 원칙 적용 + 가격 주장의 정직성 (2026-08-31)

원칙: **코드 수정 전에 전체 감사.** 그리고 **예쁜 것보다 정확한 것이 먼저.**

## 감사에서 나온 것

| 심각도 | 문제 | 근거 (실측) |
|---|------|-----------|
| **P0** | 원장의 「기록상 최저」에 **기간도 기록 하한도 없다** | `is_all_time_low = current_price <= min(전체 price_history)`. 뷰가 요구하는 최소 기록은 **2개**(`prev_price IS NOT NULL`). 카드는 `ATL_MIN_POINTS:7` 가드 + 「9일 기록 중 최저」로 기간을 밝히는데, 원장은 하한도 기간도 없이 더 센 말을 한다. 8행 중 6행에 부착 |
| **P1** | 같은 사실을 **두 자리에서 다른 기준으로** 말함 | 카드 16장 중 9장이 `.pmove`와 `.spark` 양쪽에 값. 「30일 평균보다 31% 높아요」+「▴ 3,710원」 / 「9일 기록 중 최저」+「가격 안정」 |

## P0 — 「기록상 최저」를 데이터가 보증하는 말로 좁혔다

`all_time_low` 는 **SEOSA 가 수집을 시작한 이후**의 최솟값이다. 그걸 「기록상
최저」라고 적으면 읽는 사람은 「역대 최저가」로 읽는다 — 지시 2가 금지한 주장이다.

DB·뷰·migration 은 건드리지 않고(지시 1) 화면의 말만 좁혔다.

- 「기록상 최저」 → **「수집 이후 최저」**
- `title`: "SEOSA가 이 상품 가격을 기록하기 시작한 이후로는 지금 값이 가장
  낮습니다. 기록 이전의 가격과 다른 판매처의 가격은 알 수 없습니다."

**승인이 필요해 하지 않은 것**: 원장에도 카드와 같은 7일 기록 하한을 걸려면
뷰에 `record_days` 컬럼이 필요하다 = migration. 승인 없이 하지 않았다.
그때까지는 「기간을 말하지 않는 대신 기준점을 밝히는」 쪽이 데이터가 보증하는
최대치다.

## P1 — 한 사실 = 한 표현

`.spark` 의 숫자 라벨(`▾N원` / `가격 안정`)을 없애고 **그래프만** 남겼다.
변동에 관한 말은 `.pmove` 한 곳에서만 한다.

라벨을 빼자 **평탄한 이력이 바닥 모서리에 붙은 직선**으로 그려지는 게 드러났다
(`span = (max-min) || 1` 이라 모든 좌표가 y=H 로 눌린다). 예전에는 옆의
「가격 안정」이 그 선의 뜻을 대신 말해 줬는데, 라벨을 옮기자 뜻 없는 선만 남았다.
`max === min` 이면 아무것도 그리지 않고 `.spark:empty` 로 자리까지 접는다.

실측: 양쪽 다 값 있는 카드 **9장 → 0장**, 스파크 17개 중 **6개가 접힘**.

## Apple UX 원칙과의 대응

- **Clarity** — 변동을 말하는 자리를 하나로 모아, 카드에서 「올랐나 내렸나」를
  한 번만 읽게 했다. 원장의 라벨은 기준점을 밝혀 무엇에 대한 최저인지 분명해졌다.
- **Deference** — 화면에서 가장 무거운 물체가 보조 기능(AI FAB)이던 상태를
  되돌렸다. 뜻을 잃은 그래프 선을 지웠다.
- **Depth** — 이번에는 손대지 않았다. 5차의 전환(`--ease` 하나)과 모달 depth로
  충분하고, 더하면 「애니메이션 사이트」가 된다.
