# NO_MATCH 검색 recall 분석과 조치 (2026-10-03)

운영 데이터는 **읽기 전용**(SELECT)으로만 봤다. 새 API probe 는 하지 않았다 — 수집기가 그날 실제로 낸
검색어 응답(공급자 캐시)을 그대로 대조한 «자연 실험» 이다. 정확 판정은 수집기 규칙 그대로다:
쿠팡 `productId + vendorItemId`, ADPICK `sha256(commissionlink)`. 재현: `node scripts/analyze-nomatch.js`.
집계: `reports/collector-nomatch-2026-10-03.json` (상품명·ID·검색어 원문 없음).

## 1. 분석 대상

10-02 의 상품별 NO_MATCH 목록(4,591개)은 `price_job_state` 가 매일 덮어써 남아 있지 않다. 같은 정의로
**10-03 (KST 14:25 스냅숏) NO_MATCH 5,056개 전부**를 분석했다(쿠팡 2,355 · ADPICK 2,701). 쿠팡은 그
시각 하루 예산을 이미 다 써서 확정치, ADPICK 은 이후 2,821개까지 늘었고 분포는 같다.

모든 NO_MATCH 상품은 한 번 이상 가격이 있었다. 단 «딱 하루만» 가격이 있었던 상품이 쿠팡 722개(31%),
ADPICK 1,678개(62%) — 대량 시드 당일 한 번 보이고 다시 안 나온 상품이다.

## 2. 원인 분포 (상호 배타, 위에서부터 먼저 걸리는 규칙)

| 원인 | 쿠팡 | ADPICK | 판정 근거 |

| H 정확한 상품이 오늘 다른 응답에 있었다 | 6 | 5 | 같은 identity 가 오늘 캐시에 존재 |
| NO_RESULT 검색어 응답이 0건 | 0 | 34 | 오늘 Q1 응답 items=0 |
| E 같은 제목·다른 ID (재등록 후보) | 57 | 47 | 정규화 전체 제목 일치, identity 다름 |
| **G 마지막 가격 8일+ 전, 오늘 어떤 응답에도 없음** | **1,639 (69.6%)** | **2,009 (74.4%)** | price_history 마지막 날짜 |

| **A 최근(≤7일) 가격 있는데 Q1 순위에서 빠짐** | **593 (25.2%)** | **501 (18.5%)** | 나머지 |

C·D 는 1~2% 뿐이다 — 저장된 keyword 는 이미 짧은 검색어다(쿠팡 NO_MATCH 81%, 수집 성공 84% 가 2토큰
이하). 검색어 «모양» 은 NO_MATCH 와 성공을 가르지 못한다. ADPICK 의 G 에는 «그날 시도 못 함» 이 섞인다
(ADPICK 은 매일 대상의 7~22% 를 시도하지 못한다 — 5절).

`collected_at` 은 price_history 마지막 날짜와 하루 이내로 일치한다(쿠팡 97.8%, ADPICK ≈100%) — 그래서
수집기는 추가 조회 없이 대상 행의 `collected_at` 으로 같은 구분을 쓴다.

## 3. 검색어 전략별 실측 (그날 실제로 실행된 사다리 검색어, 정확 일치만)

쿠팡, 마지막 가격 기준:

| 전략 (사다리 후보 유형) | ≤7일: 실행 / 정확 회수 | >7일: 실행 / 정확 회수 |
| --- | --- | --- |
| Q4 정리된 제목 (제목48·압축·특수문자 정규화) | 321 / 210 (65.4%) | 169 / 16 (9.5%) |
| Q2 브랜드 + 핵심 모델/명사 | 157 / 66 (42.0%) | 146 / 2 (1.4%) |
| Q3 브랜드 + 모델 + 핵심 옵션/규격 | 18 / 7 (38.9%) | 28 / 1 (3.6%) |
| Q5 모델번호 중심 | 8 / 2 (25.0%) | 11 / 1 (9.1%) |
| 꼬리 명사 단독 | 60 / 7 (11.7%) | 23 / 0 (0%) |

상품 단위: ≤7일 494개 시도 → 290개 회수(0.587, 검색어 1.14개/상품), >7일 283개 → 20개(0.071).
같은 응답에 «같은 상품·다른 옵션» 이 나온 경우가 ≤7일 Q4 에서 77회 — 옵션 불일치로 남는다(채택 안 함).
유사 제목·다른 ID 가 응답에 있던 경우 110회 — 퍼지 매칭이었다면 오매칭이 됐을 자리다. **오매칭 0**
(채택 규칙 불변). ADPICK 은 그날 사다리가 54회뿐이라(≤7일 4/27, >7일 4/27) 차이를 말할 수 없다.

1차 검색어 그룹으로 보면(쿠팡): 상품 전부가 >7일인 그룹 860개가 1차 호출 860회로 118개(0.137/호출),
전부 ≤7일인 그룹 1,105개는 926개(0.838/호출).

**결론: 검색어 모양(B/C/D)이 아니라 «그 상품이 아직 검색에 살아 있는가» 가 회수를 가른다.** 살아 있는
상품은 Q4·Q2 로 절반 이상 돌아오고, 8일 넘게 안 보인 상품은 어떤 모양으로도 10% 미만이다.

## 4. 조치 1 — 회수 사다리를 «최근 가격 있는 상품 먼저» (쿠팡, 호출 수 불변)

쿠팡은 하루 예산(3,400)을 다 쓰고 회수 라운드는 예산이 끝나는 곳에서 잘린다. 예전 큐는 «공유 상품 수»
로만 정렬돼 사실상 카탈로그 순서였고, 그날 사다리 941회 중 377회(40%)가 회수율 7% 상품에 갔다.
`api/_collectplan.js orderRecoveryQueue` 가 라운드 큐를 기대 회수량(Σ 상품별 회수 확률) 순으로 세운다.
같은 확률이면 예전 순서 그대로다. 오래 못 잡은 상품도 버리지 않는다 — 같은 라운드 뒤쪽에 선다.

같은 941회를 새 순서로 썼을 때의 추정: 최근 상품 풀 1,091개(시도 494 + 미시도 597)에서 **회수 484개
(실측 310) → +174개/일**. 미시도 상품이 시도된 상품과 같은 비율로 회수된다는 가정의 추정치다 —
배포 후 실측으로 확인해야 한다. ADPICK 은 확률표가 평탄해 순서가 예전과 같다(+0).

## 5. 조치 2 — ADPICK 미시도: 실행 시간 50분 → 85분 (분당 5회·하루 3,000 그대로)

| 확인 항목 | 실측 (09-30~10-02) |
| --- | --- |
| 실행 안 호출 간격 | 중앙값 12.3초, p90 12.4초, >13초 1.5% — sleep·직렬·DB 지연으로 버리는 시간 없음 |
| API 지연 | 중앙값 7.5초 (간격 안에 들어간다) |
| 하루 활동 시간 | 392~462분 / 1,440분 — 48칸 중 21칸만 발화, 몇 시간씩 빈다 |
| 하루 ADPICK 호출 | 1,872~2,240회 (상한 3,000) |
| 미시도 | 531 · 618 · 1,731개 (6.7% · 7.6% · 21.7%) |

동시성은 답이 아니다(분당 5회가 묶는다). 남는 것은 «일하는 시간» 이다. 실제 발화 시각으로 재현하면 실행
길이 50분 → 450분/일(실측과 일치), 70분 → 560~630분, **85분 → 680분 ≈ 3,300회 → 하루 상한 3,000 에 닿는다**.
`.github/workflows/daily-prices.yml`: `PRICE_RUN_BUDGET_MS=5100000`, `ADPICK_RUN_BUDGET=450`
(400 이면 80분에 끊긴다), `timeout-minutes: 110`. 잠금은 체크포인트(90초)가 계속 연장한다(레거시·V3
공통). 쿠팡은 실행당 700·하루 3,400 에서 먼저 멈추므로 쿠팡 호출은 늘지 않는다.

추정: ADPICK 하루 호출 +760~1,130회(상한 안), 1차 검색어 약 2,784종을 다 부를 수 있어 미시도는 0 근처.
새로 시도되는 상품은 가치 순 꼬리라 회수율이 낮다 — 35~45% 로 잡으면 +190~780개/일(미시도가 많던 날일수록 큼).

## 6. 조치 3 — 재등록 후보는 «검토 목록» 만 (자동 교체 없음)

같은 전체 제목·다른 ID 는 같은 상품이 아닐 수 있다. 실측 예: «삼성전자 AI 건조기 21kg» 35,300 → 949,700원,
«일리윤 수분크림» 8,120 → 30,300원(용량 차이), ADPICK 은 대부분 다른 판매처(롯데홈쇼핑·Hmall·SSG)의
별개 오퍼다. 유일 후보 + 가격 ±30% 를 통과해도 쿠팡 35 · ADPICK 40개. `analyze-nomatch.js --relist-out`
은 사람이 확인할 목록만 쓴다(`reviewRequired: true`). 추적 상품 ID 를 바꾸는 코드는 없다.
