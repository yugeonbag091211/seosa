### 전체 회귀에서 찾아 고친 과잉 차단 (2026-11-16, `4a1956c`)

전체 스위트(LF 체크아웃)를 돌리자 17개가 실패했고, 그중 15개는 이 브랜치 변경 전(`9c1d959`)에는 통과했다 — 관문이 만든 회귀였다. 원인별로 구조적으로 고쳤다.

- 한 글자 조사가 남아 «유닛만» 이 머리 명사가 됨 → 이번 후보 상품명이 뗀 말은 품고 붙인 말은 품지 않을 때만 뗀다(«파파야» 는 그대로)
- 영문·숫자 표기 뒤 조사(«512gb로» 의 «로»)가 필수 낱말이 됨
- 거래 말(«결제», «링크», «팔아», «색상», «사이즈»)이 상품 이름으로 요구됨
- «배터리 상태도», «배터리가 오래가는» 을 배터리를 찾는 말로 읽음
- 노트북 상품명 끝의 «… FHD IPS 한글 키보드» 를 키보드 상품으로 읽음
- «XM5» 가 «1000XM5» 의 줄임인데 낱말 전체 일치만 허용함(2글자 코드 «M3» 는 계속 낱말 그대로만)
- AI 경로에서 근거 부족 사유를 hard 로 다룸 → 위의 «실제로 쓰인 낱말» 규칙

그리고 holdout 채점 뒤 한 가지를 더 고쳤다: 관문 자체가 예외를 던지면 `/api/search` 가 검색 전체를 오류로 끝냈다. 이제는 점수 하한까지 거른 결과를 모두 «확인 안 됨» 으로 보여 주고 아무것도 저장하지 않는다(`test-product-gate` «관문 예외» 절). 관문이 던지지 않는 입력에서는 동작이 같다 — dev 180문항·재생 90문항의 판정과 지표가 한 문항도 달라지지 않았다. holdout 은 다시 채점하지 않았다.

## G. 해결하지 못한 것

1. **목표 미달**: 정확도 95%, 부속 혼동 0, 모델 불일치 0 — 위 표대로 달성하지 못했다. dev → holdout 에서 검색 79.7% → 72.8%, AI 76.3% → 67.0% 로 떨어졌다(규칙이 dev 에 일부 맞춰져 있다).

4. **실시간 확인은 12개 질의뿐**이고 그 질의는 개발 중 쓴 재생 세트에서 골랐다(C절). 운영에 배포된 코드로 확인한 것이 아니다.
