# products.keyword 오염 — 진단과 정정 절차 (2026-11-15)

운영 DB 를 **바꾸는** 단계(2·4)는 승인 전에는 실행하지 않는다. 진단(1·3)은 읽기 전용이다.

## 실측 (운영 Neon, 2026-11-15, 읽기 전용)

| 항목 | 값 |
|---|---:|
| products 행 | 78,670 (keyword 있음 78,643) |
| 관문 판정 `mismatch` (단정 사유만) | **5,626 (7.15%)** · ADPICK 3,923 / 쿠팡 1,703 |
| 그중 최근 3일 수집(화면에 뜰 수 있는) 행 | 2,482 |
| `unknown` (근거 부족 — 정정하지 않음) | 16,546 |
| 옛 규칙(토큰 하나도 없음)으로 잡히던 행 | 66 |
| 수작업 표본 정밀도 | 22/30 (운영) · 28/40 (스냅숏) ≈ **70–73%** |

**정밀도가 70% 남짓이므로 자동 정정은 하지 않는다.** 틀린 판정의 대부분은 같은 물건의 다른 이름이다
(«혈관 건강 영양제» ↔ 오메가3, «CJ 햇반 즉석밥» ↔ «햇반 12곡밥», «게이밍 체어» ↔ «게이밍의자»).
정정은 사람이 승인한 행만 한다.

화면에서는 이미 막혀 있다: 홈 섹션(`_shop.relevantRows`)이 같은 판정의 `mismatch` 를 숨기고(행은 지우지 않음),
검색·AI·크론 저장(`saveProducts`)은 확인되지 않은 상품을 그 키워드로 새로 저장하지 않으며,
수집기는 분류가 틀린 행의 카탈로그 행을 다시 쓰지 않는다(`catalogHold`).

## 절차

1. **진단 (읽기 전용)**
   ```bash
   # 연결 문자열은 환경변수로만 — 출력하지 않는다
   RO_DB_URL=... node scripts/db-quality/classify-products.js --out report.json --csv suspects.csv
   ```
   세션을 `READ ONLY` 로 고정하고 확인한 뒤에만 읽는다. SQL 만으로 보려면 `01-diagnose.sql`.
2. **검토** — `suspects.csv` 에서 정정할 행에 `approve=Y` 를 단다. 기준: 그 keyword 섹션에 이 상품이 보이면
   사용자가 «다른 상품» 이라고 느끼는가. 동의어·윗말(영양제·즉석밥·의자)은 정정하지 않는다.
3. **정정 (승인 후)** — `02-quarantine.sql` 을 한 트랜잭션으로. 승인 당시 keyword 와 지금 값이 같은 행만,
   `keyword=''` 로 비우고 옛 값은 `product_keyword_quarantine(batch_id, …)` 에 남긴다. 기록 수 = 바뀐 수가
   아니면 `rollback`.
4. **확인** — `03-verify.sql` (원장 행 수는 정정 전에 적어 둔 값과 같아야 한다).
5. **되돌리기** — `04-rollback.sql` (아직 빈 keyword 인 행만 옛 값으로. 수집기가 새로 채운 값은 지킨다).

## 오탐을 줄이는 기준 (판정 규칙)

`api/_product-gate.js` `classifyStoredRow` 의 `STORED_MISMATCH` 만 단정한다:
키워드 낱말이 하나도 없음 · 커버리지 0.2 미만 · (기기 키워드에서) 부속·부품·다른 기기 ·
모델 번호/세대/변형/용량 충돌 · 도서 · 렌탈. `category_absent`(범주 낱말 없음)는 표본 정밀도가 약 60%라 `unknown` 이다.
