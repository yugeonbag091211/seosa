# SEOSA mobile

Expo SDK 57, React Native, TypeScript, Expo Router로 만든 독립 모바일 앱입니다. 기존 웹의 `package.json`, API, Vercel 설정, Supabase 스키마를 변경하지 않습니다. 이 앱은 기존 공개 API를 **읽기만** 합니다.

## 실행

Node.js 22.13 이상과 pnpm 11을 사용합니다.

```sh
cd apps/mobile
pnpm install
cp .env.example .env
pnpm start
```

실기기 또는 에뮬레이터에서 Expo Go로 실행할 수 있습니다.

## 환경 변수

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `EXPO_PUBLIC_API_BASE_URL` | `https://seosa.ai.kr` | API 주소. `https://`만 허용하고, 개발용으로 `http://localhost`·`http://127.0.0.1`만 예외입니다. 잘못된 주소면 요청을 보내지 않고 “API 주소를 확인해 주세요.”를 보여 줍니다. |

`EXPO_PUBLIC_*` 값은 앱 번들에 그대로 들어갑니다. 서버 키(Supabase secret, 쿠팡/ADPICK/AI 키 등)는 절대 넣지 마세요. 로컬 API를 쓰려면 휴대폰에서 접근 가능한 주소가 필요합니다(`localhost`는 휴대폰 자신을 가리킵니다).

## 검사

```sh
pnpm typecheck   # tsc --noEmit
pnpm lint        # eslint (eslint-config-expo)
pnpm test        # node --test tests/*.test.mjs — API 클라이언트, 그래프 계산, 검색 세션
```

UI 렌더링 테스트 인프라는 두지 않았습니다. 대신 화면이 쓰는 판단 로직을 순수 모듈로 분리해 node 테스트로 검증합니다.

- `lib/api.ts` — 요청·타임아웃·오류 분류·응답 검증
- `lib/chart.ts` — 가격 그래프 좌표/접근성 문구(정렬, 같은 날짜 중복, 1개/평탄/큰 범위/30개 초과)
- `lib/searchSession.ts` — 검색 중복 방지, 다른 검색어로 교체, 취소, 지연 안내

## 화면

- **홈**: 브랜드, “최저가도, 고급지게.” 검색 진입, `GET /api/hotdeals?source=internal-history&limit=4&sort=score`의 실제 가격 기록 기반 딜 최대 3개, 상세 화면에서 쓰는 가격 신호(BUY / NORMAL / WAIT) 안내.
- **검색**: `GET /api/search?keyword=...`. 화면에 들어오면 입력창에 바로 포커스됩니다. 결과 카드를 누르면 상세로 이동합니다(`productId`가 없는 결과는 “상세 정보 준비 중”).
- **상세**: `GET /api/history?__route=product&pid=...&mall=...`. 상품 이미지(실패 시 브랜드 마크), 몰, 제목, 현재 표시 가격, 서버 Deal Engine 판정·이유·주의, 최근 최대 30개 관측일 그래프, 최근 관측값 5개.

API 클라이언트에는 `GET /api/history?productId=...&mall=...&vendorItemId=...&deal=1` 계약도 남아 있습니다. 상세 화면은 중복 호출을 피하려고 상품 응답에 포함된 가격 기록을 사용합니다.

## 대기·오류 정책

| 요청 | 타임아웃 | 비고 |
| --- | --- | --- |
| 홈 딜 | 12초 | 실패 시 “다시 시도” |
| 검색 | 25초 | 8초가 지나면 “조금 오래 걸리고 있어요” 안내, 언제든 “검색 취소” |
| 상세 | 15초 | 404(상품 없음)는 다시 시도 버튼 없이 안내 |

- **자동 재시도는 하지 않습니다.** 검색은 서버에서 공급자 호출과 저장이 일어날 수 있어, 다시 시도는 항상 사용자가 누를 때만 보냅니다.
- 같은 검색어를 검색 중에 다시 제출하면 무시합니다. 다른 검색어를 제출하면 진행 중 검색을 중단하고 새 검색으로 바꿉니다(이전 응답은 화면에 나오지 않습니다).
- 검색을 취소하면 직전에 보이던 결과로 돌아갑니다. 화면을 떠나면 진행 중인 요청은 중단됩니다.
- 오류 구분: 5xx → 서비스 일시 불안정, 응답 없음 → 네트워크 확인, 시간 초과 → 시간이 길어짐, 404 → 찾을 수 없음, 400 → 검색어 재입력, 읽을 수 없는 응답 → 받은 정보를 읽지 못함. 사용자가 취소한 요청은 오류로 보이지 않습니다.
- 목록 응답에서 형식이 깨진 항목 하나는 버리고 나머지를 보여 줍니다. 전부 깨졌으면 오류로 봅니다.
- 개발 빌드(`__DEV__`)에서만 실패한 요청의 경로와 오류 종류를 `console.warn`으로 남깁니다. 검색어·응답 본문·키는 기록하지 않으며, 프로덕션 빌드에서는 출력하지 않습니다.

## 알려진 제한

- 로그인, 관심상품, 푸시, AI Concierge, 오프라인 캐시, 앱스토어 배포 설정(스플래시·빌드 프로필)은 없습니다.
- 첫 검색(캐시 미스)은 공급자 응답에 따라 수 초 걸릴 수 있습니다.
- 가격 그래프는 관측일 기준 선 그래프이며 날짜 간격(빈 날)을 x축에 반영하지 않습니다.
- 앱 아이콘(`assets/icon.png`)은 투명도가 없는 정사각 이미지라 iOS 모서리 처리에 따라 가장자리가 옅게 보일 수 있습니다.
- 글자 크기(Dynamic Type/글꼴 크기)는 따르되 레이아웃이 깨지지 않도록 최대 배율을 제한합니다(본문 1.6배, 제목·컨트롤 1.3~1.4배).

## 실기기 체크리스트 (Expo Go)

1. 컴퓨터와 휴대폰을 같은 Wi-Fi에 연결하고 `pnpm start`의 QR 코드를 Expo Go로 엽니다. 연결되지 않으면 `pnpm start --tunnel`.
2. 홈: 브랜드·문구·실제 딜 목록이 보이고, 딜을 누르면 상세가 열립니다.
3. 검색: 입력창에 바로 커서가 있고, 한글로 **마우스**를 입력한 뒤 키보드의 검색 키를 누르면 마지막 글자까지 포함해 검색됩니다.
4. 검색 중 다른 검색어로 다시 검색하면 새 검색어 결과만 나오고, “검색 취소”를 누르면 이전 결과로 돌아갑니다.
5. 비행기 모드로 검색하면 “네트워크를 확인해 주세요”가, 다시 켜고 “다시 시도”하면 결과가 나옵니다.
6. 상세: 긴 상품명 줄바꿈, 큰 가격, 판정 배지(BUY / GOOD BUY / NORMAL / WAIT / DON'T BUY), 이유, 그래프의 최저·최고 라벨이 겹치지 않는지 확인합니다.
7. 상세 로딩 중 바로 뒤로 가기 → 오류나 경고 없이 이전 화면으로 돌아갑니다.
8. 다크 모드로 바꿔 홈·검색·상세의 텍스트, 구분선, 배지, 그래프, 상태 표시줄 색을 확인합니다.
9. 설정에서 글자 크기를 최대로 키워 검색창·버튼·카드가 잘리지 않는지 확인합니다.
10. VoiceOver/TalkBack으로 검색 결과 카드가 “상품명, 가격, 몰”로 읽히고, 그래프가 최저·최고·최근 가격으로 요약되는지 확인합니다.
